# 合并 main 审查标准（小功能自动化 / 主干高质量）

> 维护者：与 Multica 工作流、各子项目 Agent 规范对齐；变更时同步 `docs/DOC_HUB.md` 引用。  
> 关联：`docs/narrative/multica-tasks/2026-04-29-multica-workflow-design.md`（审查通知与状态机）

---

## 1. 原则（老大已定调）

| 层级 | 目标 | 手段 |
|------|------|------|
| **小功能 / 日常迭代** | 尽量**全自动** | CI、脚本门禁、Agent 交付前自测、自动 Review（Claude CLI / Hermes）能拦的尽量在合入前拦掉 |
| **合并到 `main`** | **高质量、可立即用** | 自动审查 + **按本文档的 P0 清单**做「合 main 门禁」；不满足则**不合并**或打回修补后再审 |

说明：**自动化**省的是重复劳动，不是省「对契约与风险的思考」——思考应固化进清单与脚本，而不是依赖「合并时再想起来」。

---

## 2. 合入 `main` 的 P0 门禁（API / 后端小功能）

凡工单描述为「新增或变更 HTTP API」「写库 JSON blob」「权限相关」，合并前**必须**满足：

1. **路径与方法**  
   - 与工单或 `@doc:` 附件**逐条一致**（含前缀，如 `/api/planner/...`、`/api/operations/...`）。  
   - 若实现有意变更契约，**必须先改文档/工单**再合，禁止「代码先行、文字后补」 silent drift。

2. **鉴权与写保护**  
   - 所有**变更类**接口（POST/PATCH/PUT/DELETE）：必须有与项目一致的认证，且**写操作**具备与现有模块对齐的权限模型（如 `require_not_viewer`、scope 等）。  
   - **读接口**若故意开放：须在 PR 说明里写一句「为何可无鉴权」；否则默认应按项目惯例保护。

3. **响应契约**  
   - 同一子系统内（如 PmSystem）**优先统一**信封（例如统一 `ApiResponse` 或统一 `{ success, data }`）；若暂时无法统一，**必须在工单或接口说明中写明**，便于前端与集成测试断言。

4. **事务与幂等**  
   - 工单若要求「单事务」「全部成功或全部失败」：实现须与之一致；**禁止**半提交后无明确错误返回。  
   - 工单若要求幂等：须能在 PR 描述或代码注释中指明判定条件（如 `sentToVersions` 已含 `versionId`）。

5. **并发写共享大对象**（如单条 `operation_matrices` JSON）  
   - 凡存在**多入口写同一 blob**：须说明并发策略；若已采用乐观锁（如 `expectedUpdatedAt`），**所有写路径**应一并评估，避免「A 路径有锁、B 路径裸写」。

6. **错误码与失败体**  
   - 校验失败返回与项目惯例一致（如 422 + 结构化 `detail`）；批量接口在「部分失败」场景下，**返回字段语义**须自洽（避免出现「已失败但计数仍显示成功」的误导）。

7. **静态与冒烟**  
   - 按子项目规范：修改文件的 Lint、关键路径冒烟（健康检查、核心页加载等）在合 main 前**已执行**；回归口径见根目录 `regression-testing.mdc` / 各项目 `AgentReadMe.md`。

8. **敏感与安全**  
   - 无密钥、无意外 broadening CORS、无 SQL 拼接等；见 `agent-core.mdc` pre-commit 门禁。

## 3. 自动 Review（Claude / Hermes）的最低产出要求

自动审查通过**不等于**可以跳过第 2 节人工核对，但审查输出**至少**应覆盖：

- 变更文件列表与工单范围是否一致（有无夹带）。  
- 是否命中第 2 节中的明显项：缺鉴权、缺事务、契约与工单不一致。  
- 若审查工具只扫风格：须在合并策略上视为**未充分审查**，须补跑清单或人工点检 P0。

---

## 4. 人工介入触发条件（不必每件都开会，但必须有人拍板）

满足**任一**则建议在合并前由老大或指定 Owner **显式确认**（可在 Multica 评论里一行「P0 已核对」）：

- 变更数据模型、迁移脚本、或不可逆数据迁移。  
- 变更鉴权模型、默认权限、或跨项目安全边界。  
- 工单范围模糊（例如「清理孤儿引用」未定义操作对象）。  
- 自动审查与自检结论冲突，或审查工具连续漏报同类问题。

---

## 5. 与「小功能全自动」的衔接

- **开发阶段**：Agent / 开发者按 `agentx.mdc` 自测 + 本文件第 2 节自检表走一遍，减少返工。  
- **审查阶段**：自动 Review 跑第 3 节；合并人（或当当规则）核对第 2 节 P0。  
- **持续改进**：每轮合 main 后发现的新坑，**优先补一条 P0 或补脚本**，避免同一类问题依赖记忆。
