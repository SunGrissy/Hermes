## B. 必问主线（按优先级排序）

### B1 WHAT 层：需求定义与目标拆解能力（最高优先级）

> **考察目标**：他是"接到需求做系统"的执行者，还是能自己定义"该做什么系统、解决什么问题、成功标准是什么"的人。

- [ ] **开场题**：「你在征途2 做新区活动体系时，'活动体系'这个需求是谁定义的？是领导说要做、还是你自己判断要做？判断依据是什么？」
  - 追问 1：「你怎么定义这套活动体系'成功了'？用什么指标衡量？指标之间有没有冲突？」
  - 追问 2：「你说首月流水超预期 15%——这个'预期'是怎么定出来的？谁定的？定的过程中考虑了哪些因素？」
- [ ] **移植题**：「假设你接手一个新项目，要做一个养成系统（类似你在冰风做的法宝养成），你拿到这个需求后的第一步是什么？不是直接出方案，而是你需要先搞清楚什么？」
  - 关键判定：是否会先追问"这个养成系统要解决什么问题""用户当前在什么阶段缺什么""商业化目标是什么"——而非直接讲"我会做几个等级、做什么材料"
  - 追问：「如果你认为这个养成系统不该做，或者做了优先级应该很低，你会怎么跟上级/制作人沟通？」
- [ ] **反事实题**：「你在神魔大陆做的新手内容改动和活动日历，如果这两个都不做，最坏会怎样？哪个更值得做？你怎么判断优先级？」

### B2 HOW 层：方案拆解与文档能力（核心验证）

> **考察目标**：他能不能把一个模糊需求拆成可交付的方案，以及他的 Spec 级文档到底写到什么程度。

- [ ] **拆解题**：「你在征途2 做的黄金国战联赛改版，从'要改版'到'上线'之间，你的工作流是什么？分几步？每步交付物是什么？」
  - 追问 1：「你写的方案文档是什么格式？里面包含哪些内容？给谁看？谁来评审？」
  - 追问 2：「'指挥结盟'和'指挥打赏'这两个功能的需求文档，程序拿到后能直接开发吗？还是需要你再口头解释很多？」（测 Spec 完备度）
- [ ] **配表与数据流题**：「你做的养成系统或活动系统中，配表是你自己设计的吗？能举一个例子——这个系统的配表结构是什么、字段怎么定的、异常数据怎么处理？」
  - 追问：「配好的表怎么验证正确性？有没有出过配表错误导致线上问题的情况？怎么防的？」
- [ ] **边界条件题**：「锁龙殿副本的龙息伤害和限时破盾，你在写需求时有没有考虑过边界情况——比如时间到了盾没破怎么办？伤害溢出怎么算？多人同时破盾怎么处理？」
  - 关键判定：是否习惯性地思考异常路径和边界条件，还是只考虑主流程

### B3 架构与框架思维（L3 核心验证 — 决定性模块）

> **考察目标**：他有没有"设计一个框架让别人在上面搭东西"的经验和思维，这是 L2 和 L3 的分水岭。

- [ ] **多系统耦合题**：「征途2 里你做了活动体系、商业化体系、反外挂体系——这三个系统之间有数据交互吗？比如反外挂积分会影响活动参与资格吗？商业化活动和常规活动共享配表框架吗？如果有，这个耦合是你设计的还是自然发生的？」
  - 关键判定：L3 应能主动设计系统间的数据流转和耦合边界；L2 通常是各做各的
  - 追问：「如果让你重新设计，你会怎么规划这三个系统之间的关系？」
- [ ] **框架复用题**：「你做了两次'活动日历'——冰风的绝世仙王和完美的神魔大陆。第二次做的时候，有没有复用第一次的设计框架？如果有，复用了什么、改了什么？如果没有，为什么？」
  - 追问：「如果要设计一个'通用活动日历框架'，让不同项目都能用，你觉得哪些部分可以抽象、哪些必须定制？」
  - 关键判定：L3 能从两次实践中抽象出可复用框架；L2 每次从头做
- [ ] **扩展性设计题**：「你设计行会神兽战时，有没有考虑过——如果半年后策划要加'行会攻城战'或'跨服行会战'，你当初的设计能扩展吗？需要推倒重来吗？」
  - 追问：「你在设计一个系统时，会为未来的扩展预留什么？具体怎么预留？」
- [ ] **快轨复用题**：「征途2 开新区时，活动内容有多少是复用的、多少是新做的？复用部分是你设计了模板，还是每次手动拷贝改参数？」
  - 关键判定：L3 应设计配置化、模板化的快轨复用机制，而非人工搬运

### B4 BUILD 层：联调落地与验收能力（实操验证）

> **考察目标**：方案到实现的最后一公里——他跟程序怎么协作，验收标准是什么。

- [ ] **联调题**：「你跟程序联调时，通常怎么对齐需求？有没有遇到过程序实现出来跟你想的不一样的情况？你怎么处理的？」
  - 追问：「你的验收标准是在什么时候定的？是开发前就写好了，还是开发完对着看？」
- [ ] **工具题**：「你做的自动化开区配置工具，这个工具的需求是你定义的还是程序自己做的？你在里面承担什么角色？工具的验收标准是什么？」
  - 关键判定：区分"我提出了工具需求并定义了功能边界"和"程序做了个工具我用了"
- [ ] **全链路追踪**：「请你选一个你最有信心的系统（比如活动日历、金箍棒神器、行会神兽战），从头到尾走一遍——最初怎么立项的、方案怎么写的、跟谁评审的、程序怎么开发的、你怎么验收的、上线后数据怎么样、迭代了什么。」
  - 这题综合验证 WHAT→HOW→BUILD 全链路，用 15-20 分钟深挖一个项目

### B5 数据闭环与迭代能力（辅助验证）

> **考察目标**：他说的"数据复盘"是真有分析体系，还是只看了个后台数据。

- [ ] **数据题**：「你提到建立了'数据复盘-快速调优'机制，具体怎么运作？数据从哪来？看什么指标？多长时间看一次？调优的决策依据是什么？」
  - 追问：「黄金国战联赛迭代了 3 次，第一次改了什么、数据变了吗、第二次为什么那么改？能说清因果链吗？」
- [ ] **归因题**：「月卡购买率提升 20%，你改了外观特权 + 每日资源定投 + 变强助手三个东西——你怎么知道 20% 里各自贡献了多少？」
- [ ] **反外挂数据**：「行为积分监控体系，积分阈值怎么定的？有没有误判正常玩家的情况？怎么处理误判？」

## C. 场景题（二选一）

### C1 系统从零设计 + 架构扩展（推荐，直接测 L3 天花板）

> 「我们有一款运营 2 年的 MMORPG，现在要加一个'师徒系统'——制作人只给了一句话：'老玩家能带新玩家一起玩，双方都有收益'。请你现场拆解：**你需要先搞清楚什么（WHAT）**、**方案怎么拆（HOW）**、**配表和验收标准长什么样（BUILD）**。给你 10 分钟。」
>
> **追加（在候选人回答完基本方案后）**：「好，现在假设半年后制作人说要加'结拜系统'——两个老玩家结拜，共享部分养成进度。你刚才设计的师徒系统，有多少可以复用？如果要设计一个'社交关系底层框架'，师徒和结拜都基于它来做，你会怎么设计？」

**评判标准**：

- WHAT 层：是否追问用户画像、核心目标、与现有系统冲突、成功指标——而非直接讲功能
- HOW 层：是否有清晰的方案结构（配对规则、奖励设计、生命周期、异常处理）
- BUILD 层：是否提到配表字段设计、与程序的接口定义、验收 checklist
- **L3 关键判定（追加题）**：是否能从两个具体系统中抽象出"关系类型 + 权限 + 奖励分发"的通用框架？能说出框架的话 = L3 潜质；只能说"到时候再设计" = L2 上沿
- 加分：是否主动考虑滥用风险（小号养大号、利益输送）、与商业化的关系

### C2 线上事故应急

> 「你负责的一个养成系统上线后，被玩家发现某个材料可以通过特定操作无限复制，已经有帖子在论坛传播。你怎么处理？请按时间线说你的动作。」

**评判标准**：

- 是否先止损（紧急下架/关闭入口）再排查
- 是否区分影响范围（多少人利用了、影响了什么经济系统）
- 回滚/补偿方案是否考虑公平性
- 是否有后续防范措施（配表校验、测试流程改进）

## 快速评分参考（1-5 分）

| 维度 | 含义 | 关键信号 | L3 门槛 |
|------|------|----------|---------|
| **WHAT 层** | 能否定义"该做什么、为什么做、成功标准"，而非只接需求 | B1 开场题的需求来源叙述、移植题的第一反应、反事实题的优先级判断 | ≥3 分 |
| **HOW 层** | 能否把模糊需求拆成完备方案，文档是否可交付给程序 | B2 拆解题的工作流清晰度、方案文档的内容描述、边界条件的覆盖 | ≥4 分 |
| **架构与框架** | 能否从具体系统中抽象可复用框架，设计系统间耦合 | **B3 全部**（多系统耦合、框架复用、扩展性、快轨模板化） | **≥3 分（L3 一票否决项，低于 3 分 = L3 不通过）** |
| **BUILD 层** | 配表能力、联调验收流程、工具化思维 | B4 联调题的协作细节、配表结构的具体度、验收标准的完备度 | ≥3 分 |
| **数据闭环** | 能否用数据验证假设、归因效果、驱动迭代 | B5 数据机制的具体度、归因题的方法论、反外挂数据的阈值逻辑 | ≥3 分 |
