## 面试主线（按优先级）

### 第一优先级：他是驱动者还是执行者？

这是决定"能不能用"的关键分水岭。标杆候选人的共性是"我来建"，而不是"我参与了"。

**开场不要让他按简历顺序自我介绍**——直接切入：

> "你在网龙干了三年多，从版本策划转到 IGG 做 PMO。请告诉我一件事：在这四年里，有哪一个流程、标准或机制是你从零搭建的？不是优化别人的，是你发起、设计、推落地的。"

追问路径：
- [ ] 如果他能给出案例 → 追到颗粒度："这个标准长什么样？举个最具体的判断标准。"
- [ ] 如果他说"完善 SOP" → 追问："完善前是什么样？你改了什么？为什么这样改而不是那样改？"
- [ ] 如果他说"流程优化" → 追问："优化前的流程跑了多久？你怎么发现它有问题？你的改法解决了什么指标？"
- [ ] **底线判断：如果他始终无法给出"我设计的规则是 X，因为 Y，结果是 Z"的完整链路 → 大概率是执行者，不是建设者。**

### 第二优先级：他理解产品吗？还是只理解流程？

他的游戏时长很亮眼（MMORPG 5000h+、SLG 中氪 1000h+），但时长≠理解。标杆候选人的产品理解不是"我玩了很多"，而是"我能从用户体验倒推设计逻辑"。

> "你 SLG 中氪 1000 小时，你觉得三谋和 ROK 在付费设计上最本质的区别是什么？不是功能区别，是它们在怎么让你掏钱这件事上有什么不同的设计思路？"

追问路径：
- [ ] 能否区分不同产品的**付费心理模型**（而不只是"这个贵那个便宜"）
- [ ] 能否从自己的付费/不付费行为倒推出设计意图
- [ ] 追问："如果你是这个 SLG 的 PM，你觉得当前版本最大的体验断点在哪里？你怎么跟策划沟通这个问题？"
- [ ] **底线判断：如果他的回答停留在"功能列举"或"我觉得挺好玩"层面 → 产品理解不足以支撑 PM 在质量判断上的发言权。**

### 第三优先级：风险识别——靠直觉还是靠机制？

他简历提到"独立对接客服处理玩家问题与重大事故""设计修复应急方案""优化回档流程"。这是验证他最有信息量的经历。

> "你提到多次在重大事故中降低损失，给我讲一个最严重的。从你怎么发现问题、到你做了什么判断、到最后结果怎么样。"

追问路径：
- [ ] 他是**被动响应**（出了事才处理）还是**主动防线**（有预警机制）？
- [ ] 事后有没有转化为制度？（赵珊珊的标杆：个案→复盘→D0 审核加强→D1/D2 比对）
- [ ] 追问："这个事故之后，你做了什么让同类问题不再发生？"
- [ ] **底线判断：如果他的风险管理停留在"救火"层面，没有"防火"机制建设 → 与标杆差距明显。**

### 第四优先级：跨部门协调的成熟度

他简历多次提到"跨部门协作"。标杆候选人的协调不是"拉个会对齐"，而是"理解各方认知框架，设计各方都能接受的方案"。

> "你在 IGG 负责跨部门协作，给我讲一个部门之间利益冲突的案例。不是信息不对称，是大家知道对方要什么但就是不同意。你怎么处理的？"

追问路径：
- [ ] 他的协调方式是**传话**（A 说了 B 要改）、**拉会**（大家坐下来聊）、还是**方案设计**（我基于双方诉求设计了一个方案）？
- [ ] 追问："对方凭什么接受你的方案？你怎么让一个比你资深的人改变立场？"
- [ ] **底线判断：如果协调方式停留在"传递信息"或"上升到老板决策" → 不具备标杆水平的协调力。**

### 第五优先级：版本管理的深度

他在网龙做了三年版本策划，这是他最长的经历。但"版本策划"和"PM"是不同角色。

> "你在英魂之刃做版本策划三年，这个角色和你现在做 PMO 最大的区别是什么？你觉得版本策划的经历，哪些能力可以直接迁移到 PM？哪些不能？"

追问路径：
- [ ] 他对"版本策划"vs"PM"的角色边界是否清晰
- [ ] 追问版本管理细节："你们的版本节奏是怎样的？封版规则是什么？插单怎么处理？"（对标赵珊珊的封版机制和插单制度）
- [ ] 追问："一个版本从规划到上线，你觉得最容易出问题的环节是哪个？为什么？你有没有针对这个环节做过什么改进？"

### 第六优先级：AI 和工具

> "你简历提到熟练使用 Jira、Git、SQL，也设计推动了 Dcloud 发布工具。AI 方面你现在怎么用？"

- [ ] 是否有在 PM 工作流中嵌入 AI 的实际案例（不是"我用 ChatGPT 写邮件"）
- [ ] Dcloud 工具的设计过程：是他提出需求并定义方案，还是别人提需求他跟进开发？
- [ ] "发布效率提升 30%"怎么算出来的？（验证量化能力的严谨度）
