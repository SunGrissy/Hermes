## 四、必问主线

### B1 沟通与表达能力（25%）—— 全程观察 + 专项探测

> **考察目标**：定性交叉面反馈的"沟通问题"——是表达能力弱、逻辑不清、还是协作推动力不足？

**全程观察指标（不用问出来，听出来）**：

| 观察点 | 正面信号 | 警惕信号 |
|--------|----------|----------|
| 回答结构 | 有主线、有层次、先结论后展开 | 想到哪说到哪、绕圈子、主题跳跃 |
| 追问响应 | 听清问题再答、不确定时会说"这个我想一下" | 答非所问、重复之前说过的内容 |
| 专业表达 | 能用设计语言精准描述（信息层级、操作路径、认知负荷） | 只能说"感觉不太好""不太对" |
| 主动性 | 会主动补充关键上下文、主动问"需要我展开讲吗" | 等着被问、回答极简不展开 |

**专项探测题**：

- [ ] **请你挑一个你最满意的交互设计项目，用 3 分钟给我讲清楚：这个功能要解决什么问题、你的方案是什么、为什么这么设计。**
  - 追问 1：如果现在让你重新给一个完全不了解这个项目的程序员讲这个方案，你会怎么讲？跟刚才给我讲的有什么不同？
  - 追问 2：你在推这个方案的过程中，有没有遇到别人不理解或不同意的时候？你怎么处理的？
  - 关键判定：能根据听众调整表达方式 = 沟通能力OK，问题可能只是面试紧张；无法调整 = 表达组织能力确实弱

**红灯信号**：
- 3 分钟讲不清楚一个自己最满意的项目
- 追问后仍然答非所问
- 对"别人不理解"的情况完全没有案例，说明可能回避冲突

### B2 设计判断力（25%）

> **考察目标**：能否从"执行交互"跨到"做设计判断"？遇到模糊需求或矛盾约束时怎么决策？

- [ ] **必问题**：你在天天玩家做了 10+ 版本迭代的合成类游戏交互。你觉得这些版本之间，交互设计上最大的差异化在哪里？这些差异是谁决定的——策划给方向、还是你自己判断的？
  - 追问 1：有没有某一次你觉得策划给的方向不对，但你还是做了？如果有，为什么没有提出来？如果没有，能举一个你主动 push back 的例子吗？
  - 追问 2：你提到"基于版本数据与用户反馈"做优化——能具体说一个从数据发现问题到改交互的完整案例吗？数据是你自己看的还是别人给你的？

- [ ] **场景题**：假设策划给了你一个需求——"做一个活动页面，要展示 8 个入口，每个入口进去有不同的玩法规则"。你拿到这个需求之后，第一步做什么？
  - 关键判定：
    - **优秀**：先追问"8 个入口的优先级是什么""用户会同时关注几个""有没有主推的"——说明有信息架构意识，不是拿到就画
    - **合格**：先做竞品参考、再出方案——有流程但缺少向上追问
    - **不合格**：直接说"我会先画几个布局方案"——纯执行思维

**红灯信号**：
- 所有设计决策都是"策划说的""需求文档写的"，自己没有判断
- 数据驱动只停在"策划给我看了数据"，自己不看不分析
- 对"8 个入口该怎么组织"没有信息架构层面的思考

### B3 跨职能协作（20%）

> **考察目标**：她的"跨职能合作"是被动配合还是主动拉齐？沟通问题在协作中如何体现？

- [ ] **必问题**：你简历里提到"主动跟进开发环节，使用 Unity3D 进行界面拼接与实现"。这个跟进具体是什么样的？是你主动去看开发进度的，还是有固定流程要你去？
  - 追问 1：你跟程序在还原交互方案的过程中，最常出现什么分歧？你怎么解决的？
  - 追问 2：有没有遇到过程序说"这个做不了"或"这个太贵了"的时候？你会怎么处理？

- [ ] **延伸题**：你到一个新团队，策划给你需求的方式和你之前习惯的不一样——比如只给口头描述不给文档，或者文档写得很模糊。你会怎么办？
  - 关键判定：
    - **主动型**：自己梳理、写下来确认、拉会对齐 = friction 系数健康
    - **被动型**：等策划补文档、或者"先按自己理解做" = friction 风险高

**红灯信号**：
- 跨职能协作全是"配合"而非"推动"
- 面对模糊需求选择"先做再说"而非"先对齐"
- 对程序的技术约束完全不了解（做了 5 年交互但不知道什么贵什么便宜）

## 五、场景题（选 1 道）

### 场景 A：需求冲突

> 策划想在一个弹窗里放 5 个按钮 + 一段说明文字 + 一张图片，你觉得信息量太大了。但策划说"运营要求必须都放上去"。你怎么处理？

**评判标准**：
- **优秀**：先理解每条信息的优先级 → 提出信息分层方案（折叠/分步/优先级排布）→ 用数据或案例说服，而非"我觉得不好看"
- **合格**：能提出替代方案，但说服方式偏主观
- **不合格**：要么全盘接受（没有判断），要么硬顶（没有沟通策略）

### 场景 B：设计还原

> 你的交互方案交给 UI 做了视觉稿，但出来的视觉稿在信息层级上跟你的交互方案有偏差——按钮优先级搞反了、次要信息太抢眼。你怎么跟 UI 沟通？

**评判标准**：
- **优秀**：用交互稿中的信息层级标注来对齐，说清楚"用户第一眼看哪里、第二步做什么"，对事不对人
- **合格**：能指出问题并给修改建议
- **不合格**："我觉得颜色不对"级别的反馈，没有设计语言
