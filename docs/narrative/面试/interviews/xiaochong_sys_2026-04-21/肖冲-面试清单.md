### B2. A 区：大富豪捕鱼深挖（20 分钟 · 考人+取经）

> **考察目标**：品类认知深度、个人角色定位、设计决策能力；同时提取节奏感/味道/商业化的有价值信息

- [ ] **A0.【开场题】你觉得大富豪捕鱼和其他捕鱼产品的关键区别是什么？**
  - 追问：你认为这种区别是怎么产生的？
  - 判定：能否抓住产品本质差异，而不只是列举功能差异

> 以下问题根据 A0 回答调整顺序，自然接话：

- [ ] **A1. 你在大富豪捕鱼里具体负责什么？** 主导了哪些系统从 0→1？
  - 追问：核心玩法循环是你定的还是制作人定的？你是执行者还是方案提出者？
  - 🔴 红灯：分不清主导和参与、所有决策归功于自己却说不清决策过程

- [ ] **A2. "捕鱼 × Slots × Pachinko 融合"这个概念谁提出来的？你怎么落地的？**
  - 追问：融合的难点是什么？三种玩法的节奏怎么统一？

- [ ] **A3. 节奏感**：你们核心玩法的节奏是怎么调的？有数值模型还是纯靠手感？
  - 追问：一局的节奏曲线大概什么样？高潮点怎么控制？用了什么手段制造"爽感"？
  - 📌 取经重点：这是我们项目最缺的部分

- [ ] **A4. "味道"**：你们的美术风格和 UI 风格是怎么定下来的？制作人对"台综感"是有意为之还是自然结果？
  - 追问：你觉得这种风格对留存有什么影响？用户对风格的反馈如何？
  - 📌 取经重点：味道是怎么做出来的

- [ ] **A5. 商业化**：你们的商业化思路和主流捕鱼/Slots 有什么不同？
  - 追问：你个人觉得哪些做法值得保留、哪些走偏了？

- [ ] **A6. 结果复盘**：这产品用户规模没起来，你觉得核心原因是什么？如果重来，你会改什么？
  - 同时测复盘能力 + 获取他的真实判断
  - 🔴 红灯：甩锅他人、无法结构化归因

### B3. B 区：专业深度验证（15 分钟）

> **考察目标**：数值感知 + 文档交付 + 品类理解 + 系统设计能力

- [ ] **B1. Boss 案例**：介绍你做得最满意的一个 Boss——从立项到上线，数值怎么定的、文档怎么交付的、最后效果怎么样？
  - 追问①：这个 Boss 的爆率/产出消耗模型是怎么设计的？
  - 追问②：开发过程中和程序/美术的协作卡点在哪？怎么解决的？
  - 🔴 红灯：说不出数值逻辑、文档只有"写了个 Excel"

- [ ] **B2. 品类异同**：Slots、柏青哥、捕鱼这三种品类，核心体验的区别是什么？做设计的时候思路有什么不同？
  - 追问：你觉得三者之间有什么可以互相借鉴的？
  - 判定：能否从体验本质层面区分，而不只是表层机制差异

- [ ] **B3. 系统耦合**：你做过的系统之间耦合最复杂的例子是什么？怎么处理数据流转？
  - 判定：有没有框架思维，还是系统之间硬编码联动

### B4. C 区：改我们产品（10 分钟）

> **考察目标**：快速判断力、方案有据、工程思维、适配度

先简单介绍我们产品的基本情况（品类、上线状态、大致形态），然后：

- [ ] **C1. Boss 维度**：如果让你来改我们产品的 Boss，你最想改哪个？或者目前没做但你觉得应该做的？

**评判要点：**

- 是否考虑了改动的成本和优先级
- 他的改法和我们团队方向是否契合

## C. 风险识别清单

| 风险项 | 探测方式 | 判定标准 |
|--------|----------|----------|
| **经验深度不足**：3 年 4 家，最长仅 11 个月 | A 区深挖具体产出 + B1 Boss 案例 | 说不清具体设计决策 = 确认 |
| **执行者非设计者** | A1"谁提的方案"、A2"谁提的概念" | 所有回答都是"按要求做" = 确认 |
| **数值短板** | B1 Boss 案例追问爆率/产出模型 | 完全没有数值框架 = 确认 |
| **稳定性**：平均每段不到一年 | 暖场直接问每次跳槽原因 | 全是被动原因且无反思 = 警示 |
| **非游戏经历 gap** | 暖场问为什么离开游戏做汽车平台又回来 | 职业规划模糊 = 警示 |
| **信息边界意识** | 全程观察 + 收尾专项题（见下方） | 见下方详细判定 |

### 信息边界意识探测

**全程观察（被动指标）：**

| 观察维度 | 低风险信号 | 高风险信号 |
|----------|-----------|-----------|
| A 区聊大富豪时 | 聊设计思路和方法论，回避具体数据 | 不加筛选地抖落内部数据、KPI、营收、团队矛盾 |
| 被追问时的边界感 | 某些问题会说"这个不太方便说"或给模糊量级 | 追问就全说，主动补充没问到的敏感细节 |
| 评价前东家的分寸 | 就事论事谈产品决策 | 吐槽制作人、贬低同事、暴露内部人事 |
| C 区聊我们产品时 | 基于公开可见信息做判断 | 提及从其他同行获得的我们的内部信息 |

**专项探测题（收尾阶段自然带出）：**

> "你之前在海外项目组做本地化，涉及多个地区的数据和策略。你们当时怎么管理信息保密的？你自己离开之后对这些信息怎么处理？"

**综合判定：**
- 被动指标全部低风险 + 专项题有边界意识 → **风险低**
- 被动指标 1-2 个高风险 + 专项题尚可 → **中等风险**，入职后需信息分级管理
- 被动指标多项高风险 + 专项题无意识 → **高风险**，慎重考虑

> 底层逻辑：一个人对前东家信息的处理方式，就是他未来对我们信息的处理方式。
