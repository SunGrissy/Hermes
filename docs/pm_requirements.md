# 游戏研发项目管理软件 - 功能需求文档

## 📋 文档概述

**项目名称**: 游戏研发项目管理系统 (GameDev PM System)  
**目标用户**: 游戏研发团队的项目经理、策划、开发、美术、QA人员  
**核心价值**: 提供轻量级、可视化的项目规划、任务分配、进度跟踪和绩效评估工具

---

## 🎯 核心功能模块

### 1. 版本管理 (Version Management)

#### 1.1 版本创建
- **用户价值**: 快速规划新版本，明确发布目标和时间线
- **功能需求**:
  - 创建版本并定义基本信息：
    - 版本名称（如 v2.5.0 春节版本）
    - 版本类型（大版本/月度活动/小更新/热修复）
    - 目标发布日期
    - 可用团队工时容量（默认800小时）
  - 选择里程碑模板：
    - 标准研发流程（30天）
    - 快速迭代流程（10天）
    - 自定义模板
  - 自动生成关键里程碑（Feature Freeze、Code Complete、QA Complete等）

#### 1.2 版本列表与选择
- **用户价值**: 快速切换不同版本进行管理
- **功能需求**:
  - 侧边栏显示所有版本
  - 版本卡片显示关键信息：
    - 版本名称、类型、发布日期
    - 当前阶段（规划中/评估中/执行中）
    - Feature数量、总工时
  - 单击选择版本，切换工作区

#### 1.3 版本删除
- **用户价值**: 清理无效或过期的版本数据
- **功能需求**:
  - 删除版本前弹出二次确认
  - 警告：删除版本将永久删除所有相关Feature和任务数据

---

### 2. Feature 管理 (Feature Planning)

#### 2.1 Feature 创建
- **用户价值**: 将版本目标拆解为可执行的功能点
- **功能需求**:
  - Feature基本信息：
    - 名称（如"新英雄-雷恩"）
    - 负责人（从团队成员中选择）
    - 当前阶段（未开始/设计中/开发中/测试中/已完成/阻塞）
    - 优先级（P0必须有/P1应该有/P2可以有）
  - 价值与工时评估：
    - 战略价值（1-10分，影响绩效计算权重）
    - 预估工时（小时）
    - 自动计算 **有效点数 = 战略价值 × 预估工时**
  - 补充信息：
    - 功能描述
    - 备注（记录关键决策、依赖、风险）

#### 2.2 Feature 列表展示
- **用户价值**: 直观查看版本内所有功能的优先级和状态
- **功能需求**:
  - 按优先级排序显示Feature卡片
  - 卡片显示关键信息：
    - Feature名称、负责人
    - 优先级徽章（P0/P1/P2配色区分）
    - 阶段徽章（带颜色区分）
    - 工时、战略价值、有效点数
  - 空状态提示："还没有添加任何Feature，点击'添加Feature'开始规划"

#### 2.3 Feature 编辑与删除
- **用户价值**: 灵活调整Feature信息和范围
- **功能需求**:
  - 点击编辑按钮，弹窗预填充现有数据
  - 更新后自动重新计算有效点数
  - 删除前二次确认

---

### 3. 阶段管理 (Phase Management)

#### 3.1 三阶段工作流
- **用户价值**: 结构化的项目推进流程，避免混乱
- **阶段定义**:
  1. **Planning (规划阶段)**:
     - 目标：定义版本范围，添加所有Feature
     - 主要操作：创建Feature、设置优先级、分配负责人
  2. **Estimation (评估阶段)**:
     - 目标：将Feature拆解为任务，评估工时
     - 主要操作：创建任务、分配团队、估算工时
  3. **Execution (执行阶段)**:
     - 目标：跟踪任务进度，监控里程碑
     - 主要操作：更新任务状态、查看燃尽图、里程碑视图

#### 3.2 阶段切换
- **用户价值**: 清晰的工作焦点，避免同时处理所有事情
- **功能需求**:
  - 顶部Tab栏切换阶段（Planning/Estimation/Execution）
  - 切换时自动更新内容区域
  - 未选择版本时提示"请先选择一个版本"

---

### 4. 任务管理 (Task Management)

#### 4.1 任务创建
- **用户价值**: 将Feature拆解为可分配的具体工作项
- **功能需求**:
  - 任务基本信息：
    - 任务名称
    - 所属Feature（从当前版本的Feature中选择）
    - 负责团队（前端组/后端组/美术组等）
    - 负责人（从选定团队的成员中选择）
  - 工时估算：
    - 预估工时（小时）
    - 实际工时（完成后填写，用于绩效计算）
  - 任务状态：
    - 待办/进行中/已完成/阻塞

#### 4.2 任务列表展示
- **用户价值**: 按Feature或团队查看任务分配情况
- **功能需求**:
  - 在Estimation阶段，按Feature分组显示任务列表
  - 显示任务卡片：
    - 任务名称、负责人
    - 团队徽章
    - 工时估算、实际工时
    - 状态徽章
  - 支持快速切换状态（拖拽或点击）

#### 4.3 工时自动汇总
- **用户价值**: 自动统计Feature和版本的总工时
- **功能需求**:
  - 创建/更新任务时，自动汇总Feature的工时
  - Feature卡片实时显示更新后的工时
  - 版本卡片显示总工时和剩余容量

---

### 5. 团队与人员管理 (Team & User Management)

#### 5.1 团队配置
- **用户价值**: 定义团队结构和可用工时容量
- **功能需求**:
  - 预定义团队职能组：
    - **美术**: 模型组、动画组、特效组、UI组
    - **程序**: 前端组、后端组、引擎组
    - **策划**: UE策划组、系统策划组、数值策划组、关卡策划组
  - 团队属性：
    - 团队名称、类别
    - 人数
    - 每周可用工时容量
    - 利用率（预留缓冲，避免100%排满）
    - 固定预留工时（维护、技术债、管理开销）

#### 5.2 人员管理
- **用户价值**: 管理团队成员，便于任务分配
- **功能需求**:
  - 添加用户：姓名、所属团队
  - 编辑用户信息
  - 删除用户（需确认）
  - 按团队分组显示成员列表

#### 5.3 容量预警
- **用户价值**: 避免过度分配，平衡团队工作负荷
- **功能需求**:
  - 实时计算团队容量消耗
  - 警告提示：
    - 🟡 容量达到80%以上：警告
    - 🔴 容量超过100%：超载
  - 版本视图显示容量进度条

---

### 6. 里程碑与时间线 (Milestones & Timeline)

#### 6.1 里程碑自动生成
- **用户价值**: 快速规划倒排时间表，避免手动计算
- **功能需求**:
  - 基于发布日期和模板自动生成里程碑：
    - 标准研发流程（30天）：
      - Feature Freeze（发布前30天）
      - 设计评审（发布前25天）
      - 美术资源交付（发布前15天）
      - Code Complete（发布前10天）
      - QA Complete（发布前3天）
      - 正式发布
    - 快速迭代流程（10天）：
      - Feature Freeze（发布前10天）
      - 开发完成（发布前5天）
      - 测试完成（发布前2天）
      - 正式发布

#### 6.2 里程碑可视化
- **用户价值**: 清晰展示关键节点和责任团队
- **功能需求**:
  - 泳道视图（Swimlane）：
    - 横轴：时间线
    - 纵轴：职能泳道（PM/Design/Art/Dev/QA）
    - 里程碑节点标注在对应泳道
  - 时间轴视图：列表显示所有里程碑和日期

---

### 7. 数据持久化与导入导出 (Data Management)

#### 7.1 本地存储
- **用户价值**: 无需后端即可使用，数据不丢失
- **功能需求**:
  - 使用LocalStorage自动保存数据
  - 支持数据版本迁移（v4→v5→v6）
  - 数据格式：
    - 版本列表
    - Feature列表
    - 任务列表
    - 团队和用户列表
    - 绩效记录

#### 7.2 导入导出
- **用户价值**: 备份数据、跨设备同步、团队协作
- **功能需求**:
  - 导出为JSON文件（包含所有数据）
  - 从JSON文件导入
  - 导入前确认提示（会覆盖现有数据）

#### 7.3 后端API集成（可选）
- **用户价值**: 多人协作、数据持久化到服务器
- **功能需求**:
  - `GET /api/data` - 加载用户数据
  - `POST /api/data` - 保存用户数据
  - `POST /api/login` - 钉钉登录
  - `POST /api/logout` - 登出
  - 401未授权自动跳转登录页

---

### 8. 绩效评估系统 (Performance Evaluation) - 未来规划

#### 8.1 绩效计算引擎
- **用户价值**: 客观量化团队和个人贡献
- **功能需求**:
  - 基础分计算：`实际完成工时 × Feature战略价值`
  - 创新加分：突破性技术、优秀设计
  - 成长加分：能力提升、知识分享
  - 扣分项：延期、返工、质量问题

#### 8.2 绩效报表
- **用户价值**: 版本复盘、绩效考核依据
- **功能需求**:
  - 个人绩效排名
  - 团队贡献对比
  - 雷达图（质量、效率、创新、协作）
  - 导出为PDF/Excel

## 🎨 UI/UX 需求

### 1. 界面布局
- **侧边栏**: 版本列表（固定宽度，可滚动）
- **顶部栏**: 
  - 应用标题
  - 操作按钮（新建版本、导入导出、登出）
- **主内容区**: 
  - 阶段Tab栏（Planning/Estimation/Execution）
  - 动态内容区域（根据选中阶段切换）

### 2. 交互体验
- **弹窗**: 
  - 模态弹窗用于创建/编辑（版本、Feature、任务）
  - 确认弹窗用于删除操作
  - ESC键关闭弹窗
- **即时反馈**: 
  - 保存后自动刷新UI
  - Loading提示（数据加载时）
  - Toast提示（成功/错误消息）
- **空状态**: 提示用户如何开始（如"还没有版本，点击创建第一个版本"）

### 3. 视觉设计
- **配色方案**: 
  - 优先级：P0红色/P1橙色/P2蓝色
  - 阶段：未开始灰色/进行中蓝色/已完成绿色/阻塞红色
  - 容量：正常绿色/警告黄色/超载红色
- **图标**: Emoji或Font Icon（清晰易懂）
- **响应式**: 支持1920x1080及以上分辨率

---

## 🔒 非功能性需求

### 1. 性能要求
- 页面加载时间 < 2秒
- 数据保存响应时间 < 500ms
- 支持管理100+版本、1000+Feature、5000+任务

### 2. 兼容性要求
- 浏览器：Chrome 90+、Edge 90+、Firefox 90+
- 操作系统：Windows/macOS/Linux

### 3. 安全性要求
- LocalStorage数据加密（可选）
- 后端API使用Cookie会话管理
- 敏感操作（删除）需二次确认

### 4. 可维护性要求
- 模块化架构（EventBus、独立业务模块）
- 代码注释和文档
- Git版本控制

## 📊 数据模型

### 1. Version（版本）
```javascript
{
  id: "v1234567890",
  name: "v2.5.0 春节版本",
  versionType: "major_expansion",  // major_expansion | monthly_event | minor_update | hotfix
  releaseDate: "2025-02-01",
  capacity: 800,                    // 总可用工时
  phase: "planning",                // planning | estimation | execution
  features: [],                     // Feature ID数组
  milestones: [],                   // 里程碑数组
  teamAllocations: {},              // 团队分配
  createdAt: "2025-01-01T00:00:00Z"
}
```

### 2. Feature（功能点）
```javascript
{
  id: "f1234567890",
  versionId: "v1234567890",
  name: "新英雄-雷恩",
  assignee: "张三",
  stage: "dev",                     // pending | design | dev | qa | done | blocked
  priority: "P0",                   // P0 | P1 | P2
  strategicValue: 8,                // 1-10分
  estimate: 40,                     // 预估工时（小时）
  effectivePoints: 320,             // strategicValue × estimate
  description: "设计并实现新英雄",
  notes: "需要提前确认美术风格",
  tasks: [],                        // Task ID数组
  actualHours: 0,                   // 实际工时
  createdAt: "2025-01-05T00:00:00Z"
}
```

### 3. Task（任务）
```javascript
{
  id: "t1234567890",

  estimate: 20,                     // 预估工时
  actualHours: 0,                   // 实际工时
```

## 🚀 开发优先级

### P0 - 核心功能（MVP）
1. ✅ 版本管理（创建、列表、选择）
2. ✅ Feature管理（创建、列表、编辑、删除）
3. ✅ 阶段切换（Planning/Estimation/Execution）
4. ✅ 数据持久化（LocalStorage）

### P1 - 重要功能
1. ⏳ 任务管理（创建、分配、状态更新）
2. ⏳ 团队管理（配置、成员管理）
3. ⏳ 容量预警（实时计算、进度条）
4. ⏳ 里程碑视图（泳道图、时间轴）

### P2 - 增强功能
1. 绩效评估（计算引擎、报表）
2. 导入导出（JSON备份/恢复）
3. 后端API集成（多人协作）
4. 高级图表（燃尽图、雷达图）

---

## 📝 总结

本需求文档定义了一个**轻量级、敏捷的游戏研发项目管理工具**，核心价值在于：

1. **快速规划**: 5分钟创建版本、添加Feature
2. **可视化管理**: 清晰的阶段视图、容量指示器、里程碑时间线
3. **灵活扩展**: 模块化架构，易于添加新功能
4. **开箱即用**: 无需后端即可使用，支持本地存储

**目标用户场景**: 10-50人的游戏研发团队，管理2-4周的迭代周期或1-3个月的版本开发。
