# Design Council 共建推进清单

> 目标：让战斗策划在 Cursor 里用上 boss-design-council 和 game-design-council，形成"设计过程中自检"的习惯。
> 原则：不是制作人推一套工具下去让他们用，是**一起用、一起改、让他们觉得这是自己的东西**。

---

## Phase 1：种子验证（1 个人 × 1 个真实方案）

**目标**：验证智囊团模式在真实场景中有没有用，同时发现第一批改进点。

- [ ] **选种子用户**：选一个对 AI 工具不排斥、手上刚好有在做方案的战斗策划
- [ ] **帮他装好**：把 `boss-design-council/` 和 `game-design-council/` 复制到他的 `.cursor/skills/` 下
- [ ] **一起跑一次**：制作人坐旁边，策划提供自己正在做的真实方案，一起看智囊团讨论
  - 观察：策划的表情和反应——哪个智囊的提问让他"愣了一下"？
  - 观察：哪些提问他觉得"问得好"，哪些觉得"这不是问题"？
  - 记录：智囊团输出中哪些术语策划没理解？
- [ ] **跑完后收集反馈**（当面聊 10 分钟，不要用表单）：
  - "你觉得最有用的是哪个智囊的哪句话？"
  - "有没有哪个问题你觉得问得不对/不懂？"
  - "你会自己再用一次吗？为什么会/不会？"
  - "你觉得缺了什么视角？"
- [ ] **基于反馈修订 SKILL.md**：改术语、调提问、补缺失视角

**Phase 1 退出标准**：种子用户愿意自己再用一次，不需要制作人陪在旁边。

---

## Phase 2：小组试用（3-5 人 × 各自的方案）

**目标**：扩大样本，收集不同方案类型下的表现，开始让策划之间产生讨论。

- [ ] **扩展到战斗策划组**：3-5 人各自安装，各自用自己的方案跑
- [ ] **建一个共享反馈文档**：简单的表格——"用了哪个智囊团 / 方案是什么 / 最有用的点 / 最没用的点 / 建议"
- [ ] **周会中加 5 分钟分享**：每周选一个人分享"智囊团给我的方案提了什么问题，我是怎么回答的"
  - 关键：分享的不是智囊团的输出，是**策划自己的回答**——这才是思考的证据
- [ ] **收集"智囊团问了但策划觉得不relevant的问题"**：这些是需要修的提问模板
- [ ] **收集"策划想问但智囊团没覆盖的维度"**：这些是需要加的智囊或提问
- [ ] **基于反馈做第二轮修订**

**Phase 2 退出标准**：至少 3 个策划在没有提醒的情况下自发使用了第二次。

---

## Phase 3：融入工作流（和预审三道门对接）

**目标**：让智囊团成为预审前的标准自检步骤，但不是强制——是"用了之后预审通过率明显更高"的自然激励。

- [ ] **建立数据对照**：记录"用了智囊团的方案"vs"没用的方案"在三道门预审中的通过率和轮次
  - 不需要严格对照实验——策划自己的体感就够（"用了之后填自检表明显顺畅了"）
- [ ] **在预审流程文档中加一行**："建议在提交预审前用 Boss/Game 设计智囊团自检一轮"——建议，不强制
- [ ] **如果视频解析平台就绪**：把平台报告格式和智囊团的输入格式对齐，实现"平台出感知，智囊团出认知"的两段式
- [ ] **考虑和 game-craft 对接**：如果 game-craft 纸上走查跑通了，在阶段四终审前自动建议"要不要先过一遍智囊团？"

**Phase 3 退出标准**：策划提交预审前自发使用智囊团成为常态（不需要提醒）。

---

## Phase 4：共建迭代（策划成为 Skill 的共同维护者）

**目标**：从"制作人的工具"变成"团队的工具"。

- [ ] **开放 SKILL.md 的修改权**：策划发现不好的提问可以自己提 PR 或直接告诉制作人修
- [ ] **建立"好问题收集机制"**：策划在使用中发现的好问题（自己想到的、智囊团没问到的），收集起来补进 SKILL.md
- [ ] **每月 Review**：花 30 分钟回顾——哪些智囊的提问命中率高？哪些从来没人觉得有用？砍掉没用的，强化有用的
- [ ] **策划可以提议新的智囊角色**：如果他们在实践中发现一个反复出现的审视维度不在六位智囊中，可以提议新增
- [ ] **版本管理**：SKILL.md 的每次修改记录在变更记录表里，标注修改来源（哪个策划的反馈）

---

## 推进注意事项

### 做

- **用真实方案推进**——不要用虚拟案例演示，策划只对自己正在做的东西有感觉
- **先让他们体验到价值再谈推广**——一个人觉得好 > 制作人说好
- **分享的是策划的思考不是 AI 的输出**——周会分享的重点是"我怎么回答的"不是"AI 怎么问的"
- **保持自愿**——强制使用的工具没有生命力

### 不做

- **不要一次推给所有人**——种子→小组→全组，每步都要验证
- **不要替他们安装和配置**——教他们自己装，自己装的东西才觉得是自己的
- **不要在推广阶段同时改 Skill**——先稳定一个版本用 2 周收集反馈，再集中改
- **不要把智囊团的讨论当绩效考核依据**——一旦和考核挂钩，策划就会"为了过关"而非"为了思考"使用它

### 风险预判

| 风险 | 信号 | 应对 |
|------|------|------|
| 策划觉得是增加负担 | "又要多做一步" | 强调自愿 + 用数据展示预审通过率差异 |
| 策划只做表面使用 | 把智囊团输出直接粘贴到自检表里 | 周会分享要求讲"我的回答"不是"AI的输出" |
| 智囊团的提问和制作人预审的标准不一致 | 策划困惑"听谁的" | 明确：智囊团帮思考，三道门定标准，有冲突以三道门为准 |
| 不同策划对同一个智囊的提问理解不同 | 同一个问题有人觉得有用有人觉得莫名其妙 | Phase 2 收集分歧，修改提问使其更具体 |
| 模型成本过高 | 策划不愿意用高级模型 | 推广单智囊聚焦模式，日常用轻量模型 |
