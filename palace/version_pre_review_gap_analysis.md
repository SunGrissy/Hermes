## 3. 共性缺口的模板/字段建议

针对每个共性缺口，建议在规划模板中增加或强制的字段/区块：

| 共性缺口 | 建议模板字段/区块 | 说明 |
|---------|------------------|------|
| **1. 版本 KPI/目标未声明** | 版本级必填字段：`version_kpi` / `core_targets` | 至少 1–2 句定性或定量目标（如留存、流水、核心体验指标） |
| **2. 版本体验主线不清晰** | 版本级必填字段：`version_theme` / `one_line_pitch` | 一句话版本定位/卖点，用于对外传播与优先级裁决 |
| **3. 管线角色未指派** | 版本级必填：`PLD` / `PLE` / `PLT` | 预审前必须指定，否则视为规划未完成 |
| **4. 付费/排期配置未纳入管理** | 新增区块：`排期配置内容清单` | 列明所有纯配置类内容、Owner、上线时间，与需设计的 Feature 区分 |
| **5. 体验表与 Feature 清单不对齐** | 预审前检查：体验表中每项有对应 Feature 或标注「排期/常驻」 | 工具或 checklist 强制：体验表条目 → Feature 或标签 |
| **6. 管线权重未标注** | Feature 清单字段：`管线权重`（快轨/慢轨） | 每个 Feature 显式标注，便于研发排期 |
| **7. 内容新鲜度未显式声明** | 版本级字段：`content_freshness_intent` | 显式声明：有意过渡/留白 vs 有新玩法，避免被误读 |
| **8. Owner 负荷分布** | Feature 清单：`Owner` 必填 + 汇总视图 | 按 Owner 汇总并行数量，超过阈值时强制提醒 |
| **9. Boss 类裸 Feature** | Boss 类 Feature 强制字段：`体验意图` / `形态说明` | 至少一句话说明差异点或机制特色 |
| **10. 视频 Boss 形态不清** | 命名规范 + 形态说明 | 若命名含「视频」，必须说明：视频广告/演出/素材等具体形态 |
| **11. 成功指标/数值锚点** | 版本级：`success_metrics`；探索类 Feature：`判定标准` | 版本至少 1–2 个定性目标；AB 测试等需预设成功/失败判定标准 |
