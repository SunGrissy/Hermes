## 2. Workflow 方案（现实路径）

### 2.1 触发机制

| 场景 | 响应者 | 说明 |
|------|---------|------|
| 群里 **@满满** 发普通任务 | 满满 | 满满分析归属，回复分配建议或直接处理 |
| 群里 **"阿茶，xxx"** 等呼直名字 | 对应 Advisor | Advisor 匹配自己的名字或被@后响应 |
| 群里随意聊天（无@、无名字） | 满满 | 满满已配置 `free_response_chats`，可监听并自动分析是否需要处理 |

### 2.2 完整流程

```
老大 @满满 → 满满分析归属 → 满满回复分配建议（"建议@xxx处理"）
                                                ↓
                                      老大手动 @对应 Advisor 转发（或 Advisor 自己看到）
                                                ↓
                                      Advisor 回复
                                                ↓
                                      老大 @满满 "验收一下"（需带上上下文）
                                                ↓
                                      满满验收汇总 → 回复结论
```

### 2.3 待定优化

- [x] **全监听**：满满已配置 `free_response_chats`，可监听群里所有消息并自动分配任务。
- [x] **主动@**：Advisor 已通过 `send_message` 实现主动群消息（如早报）。
- [ ] **上下文连续**：满满能否看到 Advisor 的回复还取决于钉钉的消息同步机制，部分场景仍需老大转发上下文。
- [ ] **复活报道**：watchdog 重启后满满主动通知老大（待实现）。
- [x] **watchdog**：已清理启动文件夹自启脚本和过时 restart bat，自动重启机制已移除。
- [x] **开机自启**：已移除 `start_advisors_silent.bat`，不再自动启动。如需开机自启请手动配置或使用 `start_all.bat`。

## 3. 技术限制

1. **Stream 机器人不能主动发群消息**：需靠 session_webhook 或额外 OpenAPI 实现
2. **全监听配置未生效**：`free_response_chats` 配置后仍需@触发，原因未查明
3. **上下文断层**：满满只能看到被@的消息，无法傈听群聊

## 4. 重启后加载配置

- 满满：配置在 `D:/hermes/config.yaml`，重启 Gateway 生效
- 阿茶：`D:/hermes/acha/config.yaml`

## 5. 开机启动命令

> 注意：所有实例共享同一个 `hermes-agent` 目录，通过 `HERMES_HOME` 环境变量区分配置。

```bash
# 满满
cd D:/hermes/hermes-agent && set HERMES_HOME=D:/hermes && venv/Scripts/hermes.exe gateway run

# 阿茶
cd D:/hermes/hermes-agent && set HERMES_HOME=D:/hermes/acha && venv/Scripts/hermes.exe gateway run --accept-hooks

# 小美
cd D:/hermes/hermes-agent && set HERMES_HOME=D:/hermes/xiaomei && venv/Scripts/hermes.exe gateway run --accept-hooks

# 妙妙
cd D:/hermes/hermes-agent && set HERMES_HOME=D:/hermes/miaomiao && venv/Scripts/hermes.exe gateway run --accept-hooks
```
