## 2. Workflow 方案（现实路径）

### 2.1 触发机制

| 场景 | 响应者 | 说明 |
|------|---------|------|
| 群里 **@满满** 发普通任务 | 满满 | 满满分析归属，回复分配建议 |
| 群里 **"阿茶，xxx"** 等直呼名字 | 对应 Advisor | 需给 Advisor 配 `mention_patterns` 匹配自己的名字 |
| 群里随意聊天（无@、无名字） | 暂无人响应 | 全监听已放弃，此场景暂不支持 |

### 2.2 完整流程

```
老大 @满满 → 满满分析归属 → 满满回复分配建议（"建议@xxx处理"）
                                                ↓
                                      老大手动 @对应 Advisor 转发（或 Advisor 自己看到）
                                                ↓
                                      Advisor 回复
                                                ↓
                                      老大 @满满 "验收一下"（需带上上下文）
                                                ↓
                                      满满验收汇总 → 回复结论
```

### 2.3 待定优化

- [ ] **全监听**：满满/子 Advisor 响应群里所有消息（已尝试，未解决，放弃）
- [ ] **主动@**：满满能主动在群里 @Advisor 分配任务（Stream 机器人缺 webhooks，需改代码或配置）
- [ ] **上下文连续**：满满能看到 Advisor 的回复（当前只能看到被@的消息，需老大转发上下文）
- [ ] **复活报道**：watchdog 重启后满满主动通知老大（待实现）
- [ ] **watchdog**：自监控自动恢复（之前版本有 bug，已停，待重写）
- [ ] **开机自启**：watchdog 随系统启动（待注册）

## 3. 技术限制

1. **Stream 机器人不能主动发群消息**：需靠 session_webhook 或额外 OpenAPI 实现
2. **全监听配置未生效**：`free_response_chats` 配置后仍需@触发，原因未查明
3. **上下文断层**：满满只能看到被@的消息，无法傈听群聊

---

## 4. 重启后加载配置

- 满满：配置在 `D:/hermes/config.yaml`，重启 Gateway 生效
- 阿茶：`D:/hermes/acha/config.yaml`
- 小美：`D:/hermes/xiaomei/config.yaml`
- 妙妙：`D:/hermes/miaomiao/config.yaml`
