# 编码执行纪律（事中 / 收尾）

本 Skill 为**单仓正本**：与根目录 `agentx.mdc`「事前路径选择」分工——规则里只保留检查点与入口；**具体执行边界**写在此处，避免在多份 `.mdc` 里重复维护。

## 1. 方案过重：事中收敛

- 写码过程中若已能判断当前实现**明显重于需求**（范围膨胀、抽象超前、无关文件牵连变多），应先**收敛实现**或**回到检查点**与用户对齐，再继续扩大改动。
- 交付前若回看 diff 仍明显过重，在自测报告中**主动说明**已做或建议做的收敛；能当场简化的优先当场简化。

## 2. 孤儿符号：只收自己造成的

- **仅清理本次改动引入**的无用 import、未使用变量、仅因本次编辑而失效的引用等。
- **不**擅自删除或「顺手整理」历史遗留的死代码、未使用导出、他人注释，除非用户**明确要求**。
- 若发现无关死代码，可**在回复中点名说明**，由用户决定是否另开任务处理。

## 何时 Read 本 Skill

- 实现类任务开始写码前（与 `agentx` 检查点一并考虑）。
- 用户或上下文强调「别改多」「最小改动」「别动旁边」时。
- 收尾与自测前，对照 diff 做一次「是否动到不该动的」自检。

## 与仓库其他约定关系

- **门禁表格式修复**、敏感信息、引用一致性等仍按 `agent-core.mdc` 与 **`preflight-checks`** Skill。
- **Checkpoint 类型与输出格式**仍以 `agentx.mdc` 为准。
