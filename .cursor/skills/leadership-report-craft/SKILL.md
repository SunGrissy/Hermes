# 向上汇报结构化方法

帮管理者把"一堆素材"变成"一份有说服力的汇报"。不是帮写漂亮话，是帮想清楚结构。

## 第一步：判断汇报类型

开始之前，必须先问清楚（或从上下文推断）：

| 类型 | 核心目的 | 结构特征 | 典型场景 |
|------|----------|----------|----------|
| **思考作业** | 展示思考深度和体系化能力 | 框架先行 → 案例佐证 → 未来规划 | VP 要你"写个思考"、战略复盘 |
| **成果汇报** | 展示做了什么、效果如何 | 案例先行 → 数据说话 → 下一步 | 季度汇报、项目总结、KPI 回顾 |

**搞反了效果打对折**：思考作业用案例堆砌会显得没深度；成果汇报用框架开头会显得空洞。

如果用户不确定，问：「老板更想看你想清楚了什么，还是想看你做出来了什么？」

## 第二步：受众校准

在定结构之前，收集以下信息：

1. **听众是谁**：直属上级？VP？跨部门？人数？
2. **听众偏好**：喜欢具体案例还是体系框架？有没有已知的关注点？
3. **政治语境**：有没有需要规避的敏感话题？需要照顾谁的面子？有没有必须提及的成果（即使不是重点）？
4. **交付形式**：口头汇报（需要演示节奏）？书面提交（需要可独立阅读）？

**关键原则**：
- 听众关心的放前面，你想说的放后面
- 如果听众有明确偏好（比如"别讲框架"或"我想看你怎么想的"），结构必须适配
- 敏感信息不是不提，是换说法：用中性描述替代具体名称，细节放附录

## 第三步：搭建叙事结构

### 思考作业模板

```
1. 开场：从一个现象/问题/案例切入（不要直接甩框架）
2. 思考维度：3 个以内的核心洞察（每个占 1-2 页）
3. 判断：基于实践的 2-3 个心得（用事实支撑，不要空谈）
4. 团队做了什么：成果全景（证明不是纸上谈兵）
5. 我做了什么：个人贡献（展示身体力行）
6. 下一步：未来规划（必须回扣前面的框架）
7. 结语：不要复述，要表态——"我确信什么"
```

### 成果汇报模板

```
1. 开场：最有冲击力的数据或场景（钩住注意力）
2. 全景：做了哪些事，覆盖多大范围
3. 重点案例：2-3 个深度案例（有数据、有对比、有因果）
4. 业务价值：节省了什么、提升了什么、避免了什么
5. 团队能力变化：不只是产出变了，人也变了
6. 卡点与需要的支持：坦诚但有解法
7. 下一步：具体、可量化、有时间表
```

## 第四步：概念穿线

好的汇报读起来像一个故事，不是 N 个散点。方法：

1. **建立统一词汇**：全篇使用一套自定义概念（如"碳基/硅基"、"快轨/慢轨"），首次出现时定义，后续直接引用
2. **回扣机制**：后面的内容必须显式引用前面的框架。例如："前面提到的'浅层→深层'三个层次，目前大部分成果还在中层，下一步要进入深层。"
3. **一条主线**：每页问自己"这页在主线的什么位置？删掉它主线会断吗？"——如果不会断，考虑删掉或合并

## 第五步：信息密度管理

| 规则 | 说明 |
|------|------|
| 一页一个核心观点 | 超过两个独立概念 → 必须拆页 |
| 数据不超过 4 组/页 | 超过就分主次，次要的放脚注 |
| 每页有且只有一个"记住这个" | 如果什么都想强调 = 什么都没强调 |
| 文字密度自检 | 如果你需要缩小字号才能塞下 → 内容太多，拆 |

## 第六步：敏感信息处理

| 场景 | 处理方式 |
|------|----------|
| 某个人/团队的负面表现 | 不点名，用"部分成员"或描述现象而非人 |
| 跨部门政治 | 只说事实和诉求，不做价值判断；需要对方配合的写"需要协同" |
| 未公开的工具/系统 | 用功能描述替代具体名称（如"钉钉消息接口能力"替代"日志机器人"） |
| 自己的成果 vs 团队的成果 | 给团队的归团队，不抢功；但个人贡献该说就说，用事实不用形容词 |
| 还没做到但计划做的 | 明确标注"规划中"，不要让听众误以为已完成 |

## 第七步：收尾力度

结语是最容易写弱的地方。常见问题和对策：

| 问题 | 对策 |
|------|------|
| 复述前面说过的话 | 不要"回顾三个要点"，要"基于这些我确信什么" |
| 开放式提问结尾 | 问题本身要有指向性，不能是空洞的"大家怎么看" |
| 太谦虚 | 思考作业可以坦诚（"还没到正收益"），但必须跟"但路已经清楚了"配对 |
| 没有前瞻 | 最后一页必须让听众知道"接下来会发生什么" |

**好结尾的特征**：听众合上文档后，脑子里留下的是一句话，而不是一堆信息。

## 与 Agent 协作建议

1. **先给素材再定结构**：把所有原始材料（会议记录、工作日志、数据）一次性给 Agent，让 Agent 先读完再提结构建议
2. **先对齐类型和受众**：在 Agent 动笔前，明确告知是"思考作业"还是"成果汇报"、听众是谁
3. **结构确认后再写内容**：Agent 提出结构大纲 → 用户确认/调整 → 再逐页填充
4. **配合 html-slide-deck Skill**：确认内容后，用 html-slide-deck 模板直接生成可演示的 HTML
