1. 适用场景与需求匹配
================================================================================

**核心玩法模式**  
**多张卡牌并行养成**：每张卡绑定独立 **point_id**，共用 **level 表**（每档 `upgrade_point`）；客户端根据积分计算等级与进度条，用于活动 UI 与汇总属性。

**典型需求场景**  
多角色/多卡牌线养成、积分驱动升级、总等级成就。

**能力标签**  
多 point、等级阈值、进度/边界两种算法、积分变化广播 `MasterCardLevelProgressChanged`。

**与相似玩法的区别**  
- **Milestone**：全活动单一进度条领奖；CardLevel **每张卡独立积分与等级**，无统一里程碑领奖逻辑于本模块。  
- **BaseBP**：经验轨道 + 付费轨；本玩法 **无** BaseBP 协议与 `gain_record` 结构。

================================================================================
2. 玩法概述
================================================================================

监听 `MasterPointChanged`：当变化的 `point_id` 属于 `conf.card_id` 中某项时，派发 `MasterCardLevelProgressChanged`。协议 `CardLevelPointConverted` 用于服务器主动校正/转换积分并派发 `PointChanged`。

================================================================================
3. 玩法类型定义
================================================================================

- `MasterPlayType.CardLevel = "MasterCardLevel"`
- 模块：`MasterPlayCardLevelModule` → `master_play_card_level_module.lua`

================================================================================
4. 核心模块说明
================================================================================

- **Init**：`MasterPointChanged` + `CardLevelPointConverted`
- **GetCardProgress** / **GetCardProgressStayBoarder**：两种进度计算（后者处理满级与段长）
- **GetCardMaxLevel**：当前实现返回 `#conf.level`（注释称各卡最大等级一致）
- **GetSumOfCardMaxLevel** / **GetSumOfAllCardLevel**：汇总用于展示或条件

================================================================================
5. 数据结构
================================================================================

- **conf.card_id**：列表项含 **point_id**（与 `MasterPointModule` 对应）
- **conf.level**：升档所需 **`upgrade_point`** 列表（升序阈值）
- **无** 独立 `info` 扩展字段要求（以服务端与配表为准）

================================================================================
6. 协议与接口
================================================================================

| 推送 | 处理函数 |
|------|----------|
| CardLevelPointConverted | OnCardPointLevelConverted |

处理成功时对 `msg.point_res`、`msg.reward_point` 分别派发 `PointChanged`（绝对值与增量语义见源码调用方式）。

**无** 本文件内的 `CreateMsg` 请求封装（由其它模块或通用入口发协议时需注意 master_play_id）。

================================================================================
7. 红点系统
================================================================================

- **未覆写** `GetRedDotKey`（无通用主红点 key）
- **InitRedDot**：仅注册 **BubbleBar** — `"MasterCardLevel_BubbleBarRedDot_"..master_play_id`
- **CalcRedDotNumber**：默认刷 0；**ManulRefreshBubbleRedDotKey** 供 UI 手动显隐 Bubble

================================================================================
8. 完成条件
================================================================================

**未实现** `CheckComplete`；卡牌升满或活动结束由配表与其它系统判断。

================================================================================
9. 开发注意事项
================================================================================

- UI 监听 `MasterCardLevelProgressChanged` 时带上 `play_info.conf.id` 与 `point_id` 过滤。  
- `GetSumOfAllCardLevel` 遍历所有卡 point 与 `level` 表，注意性能（卡数量极多时）。  
- 满级时 `GetCardProgress` 返回 `level, -1, -1`，UI 需单独处理。  
- 需要入口红点时勿假设基类行为，应在入口或子类扩展。
