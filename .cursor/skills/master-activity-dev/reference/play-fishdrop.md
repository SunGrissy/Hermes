================================================================================
1. 适用场景与需求匹配
================================================================================

- **核心诉求**：捕鱼过程中**被动掉落**指定活动道具，无需单独玩法界面操作。
- **典型活动**：活动代币/道具随鱼掉落、鱼种目标收集。
- **标签**：捕鱼掉落、被动收集、无独立红点。
- **选型提示**：只需要「局内掉落统计 + 刷新展示」、不要求玩家主动点玩法入口时选用；常与 Saga 等玩法联动鱼目标。

================================================================================
2. 玩法概述
================================================================================

模块在玩法信息刷新时从配表 `fish_drop` 解析可掉落道具列表与有效性标记；局内通过捕获事件更新 `drop_info`、`drop_count`，并向 UI/其他模块广播刷新。这是 Master 玩法中交互最轻的一类，**无独立协议收发**。

**流程摘要**：活动生效且 `is_valid` → 局内 `CatchDrop` 命中配置道具 → `OnCatchDrop` 累加 → 派发 `MasterFishDrop` / 鱼目标刷新事件。

**定位**：适合作为「子系统」挂在捕鱼主流程上，主界面往往仅展示累计进度或跳转其它玩法。

================================================================================
3. 玩法类型定义
================================================================================

- **枚举**：`MasterPlayType.FishDrop = "MasterFishDrop"`。
- **模块类**：`MasterPlayFishDropModule`，继承 `MasterPlayModuleBase`。

================================================================================
4. 核心模块说明
================================================================================

- `IsRegisterPointRequired` → **false**（不依赖积分注册逻辑）。
- **关键方法**：`GetMasterPlayIDByDropItemID`（按掉落物反查玩法）、`OnCatchDrop`（捕获时更新）。
- **事件监听**：`ANewDay`、`MasterOver`、`CatchDrop`。
- **事件派发**：`MasterFishDropRefreshForFishTarget`、`MasterFishDropNewDayClear`、`MasterFishDrop`。

================================================================================
5. 数据结构
================================================================================

- `OnMasterPlayInfoRefresh`：从 `conf.fish_drop` 构建 `drop_item_id_list`，维护 `is_valid`。
- 运行时：`info.drop_info`、`info.drop_count` 记录掉落与计数（具体字段以协议与模块实现为准）。
- **配表**：`fish_drop` 通常描述道具 ID、权重或条件；与鱼种表、房间表交叉时需策划单一数据源，避免客户端重复解析冲突。

================================================================================
6. 协议与接口
================================================================================

- **无**独立 Register 的请求/响应协议；逻辑由玩法信息推送与局内捕获驱动。

================================================================================
7. 红点系统
================================================================================

- **无**本模块专用红点键；若有入口展示需求，一般由活动外层或关联玩法承载。

================================================================================
8. 完成条件
================================================================================

- 模块内 **未实现**通用 `CheckComplete` 语义（或恒为未完成/由活动侧定义）；以产品是否配置「完成 Master 玩法」为准，勿默认可 `MasterPlayComplete`。

================================================================================
9. 开发注意事项
================================================================================

- 最简单玩法类型之一：**不要为其造复杂 UI 协议**；关注掉落 ID 与鱼种过滤一致性。
- Saga 等模块可能在 `OnMasterPlayInfoRefresh` 中写入本模块 `master_play_dict`，修改 FishDrop 刷新逻辑时注意跨模块副作用。
- 跨天事件会清理/刷新日计数，与 `CatchDrop` 顺序联调时留意。
- `MasterFishDropRefreshForFishTarget` 与 HUD 鱼目标刷新频率可能较高，避免在回调里做重逻辑或全表遍历。
- 活动多开时 `GetMasterPlayIDByDropItemID` 若返回多个候选，需与策划确认优先级（通常配表唯一映射）。
- 调试期可对比 `drop_item_id_list` 与单次 `CatchDrop` 道具 ID，快速定位配表漏配。
- 大量鱼同时死亡时优先合并刷新，避免每帧派发 `MasterFishDrop` 造成 UI 卡顿。
- 若活动要求展示「今日已掉 N 个」，与 `ANewDay` 清零顺序联调，避免跨天首局显示旧值。
- `MasterFishDropNewDayClear` 监听方应幂等，多次跨天事件不重复扣减展示数据。
- 与 `MasterOver` 同时触发时，以玩法是否仍生效为准，避免活动已结束仍累加 `drop_count`。
- 掉落物与背包满策略由全局掉落模块决定，本模块一般不截断，仅上报。
- 统计口径变更（按条/按堆叠）时与策划确认 `drop_count` 语义。
- 与「恭喜获得」联动时，掉落物展示走统一 Yield 工厂，勿手写 `YieldItemUIInfo` 字段。
- 鱼种过滤条件变更时同步 QA：限定鱼种、房间、倍率场是否仍命中 `OnCatchDrop`。
- 日志关键字建议统一为 `MasterFishDrop` + `master_play_id`，便于线上过滤。

10. 配表结构（MasterFishDrop.xls）


### Sheet: MasterFishDrop（主表）

| 字段名 | 类型 | 容器 | 说明 |
|--------|------|------|------|
| id | string | - | 玩法id |
| comment | string | - | 自己看的备注 |
| fish_drop | string | array | 掉落 / #R:FishDrop |
| go_now | object | - | 主页的按钮跳转 |
| is_room_chest | int | - | 填1走roomchest类型掉落 |
| drop_point_id | string | array | 掉落物积分id |
| point_limit_num | int | - | 掉落物持有限制，超过该值不再掉落 |
| order | int | - | 同一boss id下配置多条掉落，判断掉落的顺序。（数字越小，判断优先级越高） |
| show_hint_type | string | - | 掉落目标牌子类型， / 不填或无映射 = 【庆典目标】 / zodiac = 【守护神】 |
