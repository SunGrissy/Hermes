================================================================================
1. 适用场景与需求匹配
================================================================================

- **核心诉求**：多任务**渐进解锁**，进度主要由**服务端推送**更新，客户端合并后刷新 UI。
- **典型活动**：阶梯任务、按天/按条件解锁节点。
- **标签**：渐进解锁、服务端推送、任务完成。
- **对比**：与 `MasterUnlockPack`（付费+抽奖+自选）不同；本玩法为**纯任务/解锁进度**，无礼包付费流程。

================================================================================
2. 玩法概述
================================================================================

模块体量极小：在 `DealUnlockInfo` 中将推送消息中的结果合并进 `play_info.info.task`，再调用 `CheckComplete`；若全部任务满足条件则派发 `MasterPlayComplete`。推送注册不在本文件而在 `MasterModule`。

**流程摘要**：服务端推送 `PushMasterUnlockInfo` → `MasterModule` 转发 `DealUnlockInfo` → 合并 `task` → `CheckComplete` → 可选 `MasterPlayComplete`。

**扩展**：若任务类型变复杂（多条件、分支），优先考虑迁到 `MasterPlayTaskModule` 或 Mission 系玩法，避免本文件无限膨胀。

================================================================================
3. 玩法类型定义
================================================================================

- **枚举**：`MasterPlayType.Unlock = "MasterUnlock"`。
- **模块类**：`MasterPlayUnlockModule`，继承 `MasterPlayModuleBase`（文件约 37 行，逻辑高度集中）。

================================================================================
4. 核心模块说明
================================================================================

- **关键方法**：`DealUnlockInfo`、`CheckComplete`。
- **事件派发**：当 `CheckComplete` 在合并后通过时派发 `MasterPlayComplete`。
- **职责边界**：推送入口在 `MasterModule`，本模块只负责数据合并与完成判定，便于单测时直接 mock `DealUnlockInfo`。

================================================================================
5. 数据结构
================================================================================

- **conf.all_task**：任务 ID 列表（或等价结构）。
- **info.task[task_id]**：推送合并后的任务状态；`DealUnlockInfo` 对 `msg.res` 做 **浅合并** 到对应 `task_id`。

================================================================================
6. 协议与接口
================================================================================

- 本文件 **无** `RegisterPushHandler`。
- **推送**：`MessageType.PushMasterUnlockInfo` 在 **`MasterModule`** 注册，回调内调用 `MasterPlayUnlockModule.Instance:DealUnlockInfo(msg)`。

================================================================================
7. 红点系统
================================================================================

- 本模块 **未定义**专用红点键；入口红点由活动或其它模块按需实现。

================================================================================
8. 完成条件
================================================================================

- 对 `conf.all_task` 中每个 `task_id`：`info.task[task_id].s >= 1`（任务均达成/已领，具体语义以配表为准）。

================================================================================
9. 开发注意事项
================================================================================

- 修改推送字段时同时改 `MasterModule` 与 `DealUnlockInfo`，勿只改一端。
- 浅合并：嵌套表若需深度合并应在服务端保证结构或扩展合并逻辑。
- 文件极短，扩展新能力前评估是否应迁到更通用 Task 模块以免继续膨胀 `MasterModule` 分支。
- 任务 `s` 字段语义（已领/已完成）以配表注释为准，联调时打印 `task_id` 与合并前后表便于排查。
- 若需红点，建议在独立模块或 UI 监听 `info.task` 变化，勿强行塞进本文件破坏单一职责。
- 推送乱序时多次 `DealUnlockInfo` 应仍能得到单调进度，必要时以服务端时间戳为准。
- 任务 ID 与活动多开实例混用时，确认 `master_play_id` 隔离，避免 task 表串数据。
- 全量任务完成后若有后续剧情，勿在 `CheckComplete` 里写死，改由活动控制器驱动。
- 回归测试覆盖「最后一条任务完成瞬间」推送与 `MasterPlayComplete` 只触发一次。
- 任务配置热更后，已满足条件的任务应下一次推送即能 Complete，勿要求客户端重启。
- 与引导强绑时，注意 `MasterPlayComplete` 与引导步骤的先后顺序，避免引导卡死。
- 若任务含「分享」类外链，完成判定以服务端回调为准，客户端勿本地先行 Complete。
- 多语言下任务描述与 `task_id` 映射勿硬编码中文 key。
- 与 GM 指令配合时，`DealUnlockInfo` 应能处理补发全量任务快照。
- 活动复用模板时注意 `all_task` 去重，避免同 ID 重复 Complete 判定异常。
- 性能：任务数量极大时 `CheckComplete` 可改增量判断，避免每推送全表扫描（需与程序约定）。

10. 配表结构（MasterUnlock.xls）
================================================================================

### Sheet: MasterUnlock

| 字段名 | 类型 | 容器 | 说明 |
|--------|------|------|------|
| id | string | - | 唯一ID |
| comment | string | - | 注释 |
| action_trigger_events | TriggerEvent | array | 触发的行为条件；该条件在unlock_requirements、register之后开始计数，多个条件之间是or的关系，引用 TriggerEvent 子表 |
| act_id | string | - | 引用的masteract活动id |

### Sheet: TriggerEvent

| 字段名 | 类型 | 容器 | 说明 |
|--------|------|------|------|
| id | string | - | 唯一ID |
| comment | string | - | 备注名 |
| task_action | string | - | 具体的任务条件类型 |
| task_filters | object | array | 过滤事件 |
| task_value | object | - | 如何累加值 |
| rewards | yield | array | 完成本任务可领的奖励 |
| go_now | object | - | 跳转配置，如果不为空，任务没完成时显示“前往”按钮，点击跳转到配置的界面 |
