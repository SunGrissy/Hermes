# 与 Agent 协作做内容的方法

让 Agent 成为思考伙伴，不是打字员。核心原则：**你管方向，Agent 管执行。**

## 谁该读这个

任何需要用 AI 做内容创作的人——写报告、做方案、准备汇报材料、整理文档。不限于 Cursor，适用于所有 AI 协作场景。

## 三种协作模式

### 模式 A：你有素材，Agent 帮你组织

**场景**：手上有一堆会议记录、工作日志、数据，需要整理成结构化的文档。

**流程**：
1. 把所有素材一次性给 Agent（不要挤牙膏，一次给全）
2. 告诉 Agent 目标受众和用途（"给 VP 看的季度思考"、"给团队的分享材料"）
3. 让 Agent 先出结构大纲，你确认后再写正文
4. 正文出来后，逐章给反馈

**常见误区**：只给一部分素材 → Agent 理解片面 → 结构歪了 → 推倒重来。

### 模式 B：你有想法，Agent 帮你成型

**场景**：脑子里有思路但还没成文字，需要 Agent 帮你把想法变成可读的内容。

**流程**：
1. 先口语化地说清楚你的核心观点（不需要组织语言，说人话就行）
2. Agent 出第一版 → 你看了之后说"这里的重点不是 X 而是 Y"
3. 几轮下来，文字会越来越接近你脑子里的意思

**关键**：你不需要告诉 Agent 怎么改每个字，只需要说"方向不对"或"重点偏了"。

### 模式 C：你有框架，Agent 帮你填充

**场景**：结构已经定了，需要 Agent 按框架填内容。

**流程**：
1. 把框架（目录/大纲/模板）给 Agent
2. 逐节指定要点："第三章重点讲 XXX，数据来自 YYY"
3. Agent 填完一节，你确认后再填下一节

**适合**：PPT 每页的内容填充、固定格式的报告撰写。

## 高效反馈的五种句式

好的反馈 = Agent 一轮就能改对。以下是从实战中总结的高效句式：

### 1. 指出逻辑关系（而非改文字）

```
❌ "把第二段改成……"
✅ "这两个概念不搭嘎，它们其实分别属于 X 和 Y 的逻辑"
```

Agent 理解了逻辑关系，会自己决定怎么改文字、怎么调结构。

### 2. 说你想强调什么（而非怎么强调）

```
❌ "把这句话加粗并放大字号"
✅ "我想强调的不是'我不会代码'，而是'我是最忙的人都能做到，没人有借口'"
```

Agent 会自动选择合适的视觉表达方式。

### 3. 说感觉哪里不对（Agent 来诊断）

```
❌ （自己琢磨半天怎么改）
✅ "这一页感觉虎头蛇尾"
✅ "快轨慢轨和钉钉机器人放一页有点怪"
```

你只需要说出感受，Agent 会分析原因并给出方案。

### 4. 补充你的真实意图

```
❌ "信息基建那里改一下"
✅ "这两条说的其实是如何完善对碳基和硅基都友好的基础建设"
```

当 Agent 的理解和你的意图有偏差时，直接说出你的理解，Agent 会按你的意图重新组织。

### 5. 给选择而非给指令

```
❌ "去掉这个编号"
✅ "这些编号要么去掉，要么在后面加编号呼应。你的建议？"
```

让 Agent 分析利弊再给建议，通常比你自己拍脑袋决定更全面。

## 节奏控制

| 阶段 | 你做什么 | Agent 做什么 |
|------|----------|-------------|
| 启动 | 给全量素材 + 说清目标受众 | 读完素材，提结构建议 |
| 定结构 | 确认/调整大纲 | 按大纲出初稿 |
| 逐章打磨 | 每章给方向性反馈 | 改写、调整、补充 |
| 收尾 | 整体审阅，指出"差点意思"的地方 | 强化收尾、统一风格 |

**节奏铁律**：
- 不要在定结构之前就纠结文字——先对后好
- 不要一次给十条反馈——每轮 1-3 条，改完再给下一批
- 看完整体再给反馈，不要边读边提——容易前后矛盾

## 什么时候该自己写

Agent 擅长组织、填充、美化，但以下场景你最好自己写初稿：

- **高度个人化的表达**：你的管理哲学、你对团队的判断、你的价值观表态
- **政治敏感的措辞**：涉及人事、利益冲突、组织政治的内容
- **灵感性的金句**：Agent 能写出正确的话，但很难写出有灵魂的话

写完后可以让 Agent 帮你润色和嵌入整体结构，但内核得是你自己的。
