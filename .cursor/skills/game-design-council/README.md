# 游戏设计智囊团

**用认知科学的六个视角，帮策划在玩法/系统设计过程中自检方案。**

不是检查清单，不是评分表——是一场围绕你的方案的专家讨论。六位智囊各自提问、交叉补充，你在讨论中发现自己的盲区。

适用于所有游戏玩法/系统/经济/社交/运营设计，不限品类。

---

## 六位智囊一览

| 角色 | 守护维度 | 一句话 |
|------|---------|--------|
| 🎯 目标感守护者 | 目标清晰度与层次感 | 玩家任何时刻都该知道自己在追求什么 |
| 🔄 循环诊断师 | 核心循环的节奏与变化 | 好循环 = 压力释放交替 + 每次有微变化 |
| ⚖️ 公平感审计师 | 分层公平与付费边界 | 不公平的记忆比爽感的记忆持久得多 |
| 🎰 惊喜工程师 | 随机性、预期管理与保底 | 乐趣来自预期差，不来自奖励本身 |
| 🌊 生态观察者 | 系统间交互与长期后果 | 直接效果看得见，连锁反应才真正危险 |
| 🧪 首次体验官 | 新手前 5 分钟的体验 | 前 5 分钟的权重超过后面 5 小时 |

## 核心设计哲学

- **苏格拉底式**：智囊提问，策划回答。答案由人给出，不由 AI 裁决
- **助推而非强制**：通过讨论引导策划自己发现问题，不是列检查清单
- **认知科学驱动**：每位智囊的判断标准都有学术依据，但面向策划用设计语言表达
- **与 game-review 互补**：智囊团帮内化标准做过程自检，game-review 做正式终检

## 适用场景

- 玩法/系统/经济/社交/运营设计方案的任何阶段自检
- 设计到一半"哪里不对但说不清"时的诊断
- 收到制作人审核反馈后想深入理解反馈逻辑
- 策划之间的方案互评讨论
- game-craft 产出的方案在提交终审前的自检

## 部署指南

### 方式一：Cursor 原生 Skills 目录

```
1. 将 game-design-council/ 目录复制到项目的 .cursor/skills/ 下
2. 或复制到全局 Skills 目录：
   - Windows: %USERPROFILE%\.cursor\skills\game-design-council\
   - macOS/Linux: ~/.cursor/skills/game-design-council/
3. 新开 Cursor Agent 会话即可生效
```

### 方式二：单文件手动安装

```
1. 复制 SKILL.md 的全部内容
2. 在 Cursor 中创建 .cursor/skills/game-design-council/SKILL.md
3. 粘贴内容，保存
```

### 验证安装

新开一个 Agent 会话，输入以下任一句话：

```
"玩法智囊团"
"帮我讨论一下这个方案"
"系统设计讨论"
```

Agent 应识别并加载本 Skill，以六位智囊的讨论格式回应。

## 注意事项

### 对使用者（策划）

1. **智囊团不给"通过/不通过"的结论**——他们给你 2-3 个需要你自己回答的问题
2. **不要把讨论当标准答案**——"好不好玩"的最终判断是你的 sense
3. **讨论后要有动作**——每轮讨论后应有具体修改
4. **概念阶段别急着问经济细节**——核心循环没定就讨论通胀是浪费
5. **模型不够强时用单智囊模式**——对 Agent 说"公平感审计师帮我看看"就能单独深度讨论
6. **方案来源不限**——手写的、game-craft 生成的、竞品分析来的都行

### 对 Agent

1. **角色边界严格**：每位智囊只发表自己维度的意见，不越界
2. **先肯定后提问**：每位智囊先说方案做得好的部分，再提问题
3. **用设计语言不用术语**：面向策划说"同时展示太多了"而非"工作记忆超出 4±1 组块容量"
4. **结尾推回不确定性**：不给通过/不通过结论，给需要策划自己回答的问题
5. **阶段适配**：概念阶段只启动目标+循环两位智囊，完整方案才全员上场
6. **不替代 game-review**：本 Skill 是思考伙伴，game-review 是审核工具，两者互补不冲突

### 与其他设计工具的关系

```
日常设计过程 ─→ game-design-council（随时自检）
Boss 表演设计 ─→ boss-design-council（专项自检）
方案完成提交 ─→ game-review（正式审核）
从零生成方案 ─→ game-craft → game-design-council → game-review
```

## 实现原理

### 架构：六角色 × 认知科学映射

```
┌─────────────────────────────────────────────┐
│              策划的设计方案                    │
└──────────────────┬──────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│          Agent 判断方案完成度阶段              │
│     概念 / 草案 / 完整方案 → 匹配智囊权重     │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│            六位智囊依次发言                    │
│                                              │
│  🎯 目标感  ← 目标梯度效应, 认知评估一致性,   │
│               心流-清晰目标                   │
│  🔄 循环    ← 认知负荷三分类, 系统1/2交替,    │
│               PREE, 心流通道                  │
│  ⚖️ 公平感  ← 损失厌恶2x, 归因理论,          │
│               杏仁核快通道                    │
│  🎰 惊喜    ← PEL预测误差, 可变比率强化,      │
│               Near-miss, 习得性无助           │
│  🌊 生态    ← 二阶效应, 沉没成本,             │
│               IKEA效应, 损失厌恶              │
│  🧪 首次    ← 工作记忆4±1, 杏仁核首次印记,    │
│               渐进披露, 10秒理解               │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│              讨论汇总                         │
│  共识 + 分歧 + 需策划回答的2-3个问题           │
│  （不给通过/不通过结论）                       │
└──────────────────────────────────────────────┘
```

### 与 boss-design-council 的共享与差异

| 维度 | 共享 | 差异 |
|------|------|------|
| 认知科学底座 | ✅ 相同的学术理论体系 | 提问模板和红灯判断完全不同 |
| 讨论协议 | ✅ 先肯定后提问、不做裁判、推回不确定性 | boss 版有视频拆解表和平台报告接入 |
| 智囊角色 | 部分重叠（注意力、预期） | boss 版有冲击力审计师和节奏指挥，本版有目标感守护者和生态观察者 |
| 适用对象 | 都面向策划 | boss = Boss 加分表演，本版 = 通用玩法系统 |
