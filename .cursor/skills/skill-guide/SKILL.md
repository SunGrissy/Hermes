# Skill 写作指南

面向 Agent 和人类的统一 SKILL 编写指南。

## 触发条件

- 用户要求创建新 Skill
- Agent 根据 `skill-evolution.mdc` 提议创建
- 用户问"SKILL 是什么""怎么写 SKILL"

## SKILL.md 标准模板

```markdown
---
name: [小写字母-连字符]
description: >-
  Use when [触发条件]. 触发词：「关键词1」「关键词2」
---

# [名称]

> 一句话说明

## 什么时候用 / 不用

## 工作流程（Agentic Protocol）
### Step 1: 分类（理解输入）
### Step 2: 研究（按需获取信息）
### Step 3: 输出（结构化交付）

## 判断框架

## 做不到什么（诚实边界）

## 变更记录
```

## 编写五原则

1. **Agentic Protocol**：分类→研究→输出，不是规则罗列
2. **诚实边界**：具体说做不到什么，不是"AI有局限"
3. **可验证性**：判断标准可量化或可观测
4. **面向场景**：围绕用户会遇到的场景，而非技术功能
5. **自包含**：新 Agent 仅凭此文档能独立执行

## 面向人类的引导流程

### 判断层级

| 信号 | 层级 | 行动 |
|------|------|------|
| "SKILL 是什么" | 扫盲 | 类比解释 + 举例 |
| "帮我写一份" | 入门 | 对话追问提炼经验 |
| "帮我优化" | 进阶 | 按质量清单审查 |

### 入门：对话追问（不让用户自己填模板）

1. 你要教 AI 做什么事？
2. 你做这件事时第一步干什么？然后呢？
3. 做这件事最容易踩什么坑？
4. 什么情况下这个方法不管用？

追问完毕后生成 SKILL 文档，主动提出验证。

### 进阶：质量检查清单

- [ ] description 只写触发条件，不含工作流摘要
- [ ] 有三步工作流（不是规则罗列）
- [ ] 有至少 1 条诚实边界
- [ ] 新 Agent 仅凭此文档能独立执行
- [ ] 与现有 Skill 无重叠或已标注边界
- [ ] README.md 已更新

## 局限性

- 本指南适用于 Cursor `.cursor/skills/` 体系
- 不覆盖需要外部运行时的 Skill 设计
- 游戏业务类 Skill 的领域验证需制作人参与
