# 设计审核工具（Design Review）

三合一审核：通用策划方案 / Boss 预审 / Feature WHAT。Agent 根据审核对象自动选择模式。

## 模式选择

| 信号 | 模式 | 说明 |
|------|------|------|
| 策划方案、系统设计、活动方案 | **通用审核** | 6引擎检查 + 决策问题 |
| Boss 表演、概念门/结构门/制作门 | **Boss 预审** | 三道门标准 |
| Feature 设计、WHAT 层、体验意图 | **Feature WHAT** | 四条判断标准 |

---

## A. 通用策划方案审核（原 game-review）

核心原则：**AI做逻辑完整性检查（快+全），人做直觉判断（不可替代）。**

### 六大检查引擎

| 引擎 | 代号 | 核心问题 |
|------|------|---------|
| 设计目的检查 | Purpose | 目的是否清晰、一致、服务目标人群 |
| 情绪节奏分析 | Rhythm | 情绪曲线是否有波峰波谷 |
| 红线与误区扫描 | RedLine | 是否触碰红线、命中误区 |
| 价值冲突检测 | Value | 价值排序是否被违反 |
| 玩家分层评估 | Segment | 各分层影响、中坚层是否被保护 |
| 经济系统健康度 | Economy | 通胀风险、重置策略、追赶机制 |

引擎 reference 文件位于 `references/` 子目录。

### 引擎裁剪

| 方案类型 | 必要引擎 | 可选引擎 |
|----------|---------|---------|
| 完整策划案 | 全部6个 | — |
| 单系统设计 | Purpose, Rhythm, RedLine | Value, Segment, Economy |
| 数值方案 | Purpose, RedLine, Economy | Rhythm, Value, Segment |
| 活动/运营方案 | Purpose, RedLine, Value | Rhythm, Segment, Economy |

### 直觉层决策问题

三种类型：**Gate**（必须等人回答）、**Flag**（人可推翻AI结论）、**Sense**（直觉裁决）。每轮 ≤3 个。

### 制作人方法论核心

- 价值排序：公平感 > 社交生态 > 爽感 > 留存 > 付费
- 三条红线：核心循环不为KPI让步、不强迫玩家、不做冗余系统
- 五大误区：堆系统当内容、数值解决体验问题、过度参考竞品、前期过度披露、设计给自己玩

## B. Boss 预审三道门（原 boss-precheck-review）

### 核心设计原则

| 原则 | 含义 |
|------|------|
| 答案即证据 | 自检表是填空题不是判断题 |
| 改结构不加特效 | 向后读、分支不可读是结构问题 |
| 纸面优先 | 结构问题必须在结构门暴露 |
| 着急 > 拖沓 | 优先保证认知参与时间 |
| 一次只讲一件事 | 限制并发，不限密度 |

### 概念索引

| 概念 | 一句话 |
|------|--------|
| 向前读 vs 向后读 | 合格：事发前画面已让玩家产生预期 |
| 信号→赌注→揭晓 | 分支可读的三段；缺任一段悬念价值归零 |
| 逼近→定帧→余韵 | 关键时刻的三层时间结构 |

### 三道门标准摘要

**① 概念门**（5条）：调性重量、情绪概念冲击、拥有欲+一致性、玩法新鲜感、视觉新鲜度

**② 结构门**（4条）：叙事可读性（向前读）、蓄力-释放、分支可读性（信号/赌注/揭晓）、段间递进

**③ 制作门**（6条）：蓄力-释放+时间操控（硬门槛）、计分与情绪绑定、镜头叙事、段间递进执行、"那个瞬间"、演出可信度

### 制作门扩展：演出可信度

| 检查项 | 核心问题 |
|---------|---------|
| 动画-数值一致性 | 动画揭晓前后与数值高低是否一致？ |
| 情绪曲线一致性 | 动画长度/强度是否符合情绪曲线？高分是否给了更强的演出？ |
| 误导性 | 是否误导玩家相信本次会是高分？（长期信任损耗风险） |

权威全文见仓库根目录 `Boss预审_*.md`。

## C. Feature WHAT 审查（原 feature-what-review）

核心问题：**这个 Feature 的 WHAT 想清楚了吗？**

### 四个判断条件

1. **能用一句话说清楚玩家的情绪目标**——不是"功能做什么"，是"玩家打开想感受到什么"
2. **知道"做对了"和"做坏了"的区别**——北极星 / 分层 / 红线三把尺
3. **信息从玩家视角组织**——"打开就知道该干嘛" vs "自己找答案"
4. **决策口已关闭，下游可以直接开工**

### 讨论时优先追问

1. "你希望玩家打开时心里冒出的第一个念头是什么？"
2. "做得特别好/做歪了，你怎么知道？"
3. "这个设计是帮玩家找答案，还是让玩家看系统能给什么？"
4. "有没有什么决策还悬着，让UX不知道从哪里开始？"

### 红灯信号

- 描述只有机制没有情绪
- 成功标准是"玩家喜欢"（不可量化）
- 每个付费层级体验相同（分层没想）
- 大量"到时候再定"的核心项（决策口没关）

## 输出格式（通用）

```
【模式】通用审核 / Boss预审 / Feature WHAT
【结论】通过 / 待改进 / 不通过
【核心问题 Top3】（每条：标准编号 + 现象 + 建议方向）
【需补充材料】（如适用）
```
