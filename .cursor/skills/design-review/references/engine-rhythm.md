# 引擎2：情绪节奏分析（Rhythm）

## 检查目的

判断方案的情绪曲线是否有波峰波谷设计，是否存在"情绪平原"（长时间无情绪波动的段落）。

> **方法论来源**：制作人设计哲学——"好游戏设计 = 给玩家创造丰富的情绪体验"。
> 致命缺陷特征："看起来完整但破坏了玩家情绪释放的周期性节奏。"

## 检查项清单

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|---------|--------|
| 1 | 压力-释放周期 | 是否存在明确的压力期→释放期交替？ | P0 |
| 2 | 情绪维度覆盖 | 六大维度（目标感/新鲜感/成长感/社交压力/叙事性/随机性）覆盖了几个？目标感必须覆盖 | P1 |
| 3 | 成长波峰波谷 | 成长体验是否有起伏而非线性增长？ | P1 |
| 4 | 情绪平原检测 | 是否存在长时间（如连续2周+）无情绪波动的段落？ | P1 |
| 5 | 循环周期节奏 | 循环周期是否随时间合理拉长？ | P2 |
| 6 | 宏观期待感 | 是否定期给玩家新鲜的东西以塑造期待？ | P2 |

## 子代理 Prompt 模板

```
你是情绪节奏分析引擎（Rhythm Engine），负责审核策划方案的情绪曲线设计。

## 你的方法论
先阅读制作人方法论：[producer-methodology.md 路径]
重点关注第1章"设计哲学"和第2章"成长节奏理论"。

核心理论：
- 前10分钟就要有"差一点挂了→质变→割草"的体验循环
- 循环周期逐步拉长，爽感不一定持续放大
- 宏观上需要压力期和释放期交替，定期注入新鲜内容塑造期待
- 致命缺陷 = 破坏情绪释放的周期性节奏

## 审核对象
[文档路径]

## 检查要求
1. 尝试绘制方案的情绪曲线（用文字描述各阶段的情绪起伏）
2. 识别压力期和释放期的分布
3. 检查六大情绪维度的覆盖情况
4. 标注可能存在的"情绪平原"段落
5. 评估成长体验的波峰波谷设计

## 输出格式
- 情绪曲线描述（各阶段的情绪起伏）
- 检查项表格
- 情绪平原标注（如有）
- 问题清单（带优先级）
- 维度评分（10分制）
```

## 边界条件

- 工具型/辅助型系统（如背包、设置界面）：不要求完整情绪曲线，标注"低置信度"
- 短期活动方案：压力-释放周期可在更短时间尺度上评估
