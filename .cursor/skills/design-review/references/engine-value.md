# 引擎4：价值冲突检测（Value）

## 检查目的

检测方案中是否存在低优先级目标压过高优先级目标的设计冲突。

> **方法论来源**：制作人价值排序——"公平感 > 社交生态 > 爽感 > 留存 > 付费"。
> 公平感定义："不是绝对数值平等，是感知层面的可接受度。"

## 排序基准

```
公平感（感知可接受度）
  > 社交生态（生态健康、中坚层稳定）
    > 爽感（情绪体验强度）
      > 留存（D1/D7/D30等指标）
        > 付费（收入、ARPU等）
```

## 检查项清单

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|---------|--------|
| 1 | 排序违反 | 方案中是否存在为了提升低优先级目标（如付费）而损害高优先级目标（如公平感）的设计？ | P0 |
| 2 | 付费增量控制 | 付费玩家的每日增量是否在不让非付费玩家感到沮丧的范围内？ | P1 |
| 3 | 免费下限保障 | 免费玩家通过每天劳作，能否获取等价约20-50美金的付费产出？ | P1 |
| 4 | 逼氪检测 | 是否存在不符合本地消费习惯的强制付费设计？ | P0 |

## 子代理 Prompt 模板

```
你是价值冲突检测引擎（Value Engine），负责检测策划方案中的价值排序冲突。

## 你的方法论
先阅读制作人方法论：[producer-methodology.md 路径]
重点关注第3章"价值排序"。

核心排序：公平感 > 社交生态 > 爽感 > 留存 > 付费

关键定义：
- 公平感 ≠ 绝对平等，= 感知可接受度
- 付费变强不是不公平，但每日增量必须控制
- 免费玩家日产出下限 ≈ 20-50美金等价付费产出

## 审核对象
[文档路径]

## 检查要求
1. 识别方案中涉及的价值目标（公平/社交/爽感/留存/付费）
2. 检查是否存在排序违反（低优先级压过高优先级）
3. 如涉及付费设计，检查增量控制和免费下限
4. 如涉及本地化，检查是否存在逼氪

## 输出格式
- 价值目标识别
- 冲突点列表
- 问题清单（带优先级）
- 维度评分（10分制）
```

```markdown

- 方案可能影响的目标：[列出]

**冲突检测**：

| 冲突点 | 涉及目标 | 排序是否违反 | 严重度 |
|--------|---------|-------------|--------|
| ... | ... | ... | ... |

**付费公平性检查**（如适用）：
- 付费每日增量：[评估]
- 免费日产出下限：[评估]

**维度评分**：X/10
```

## 边界条件

- 纯PVE方案：公平感检查放宽（无直接对抗场景）
- 纯商业化方案（如礼包设计）：重点检查逼氪和增量控制
