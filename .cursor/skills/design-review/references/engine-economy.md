# 引擎6：经济系统健康度（Economy）

## 检查目的

评估方案的经济系统是否存在通胀风险、重置策略是否合理、是否有追赶机制。

> **方法论来源**：制作人判断——"经济系统最难救，通胀一旦失控回收极难。"
> 重置策略："付费养成不重置只扩展，非付费可赛季重置，50%满级触发追赶+加层。"

## 检查项清单

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|---------|--------|
| 1 | 通胀风险 | 资源产出是否有无限膨胀的可能？是否存在只产出不消耗的资源？ | P0 |
| 2 | 付费/赛季乘区分离 | 付费养成和赛季成长是否在不同乘区（乘法关系而非加法）？ | P1 |
| 3 | 追赶机制 | 是否存在后发玩家追赶先发玩家的路径？50%满级后是否有追赶设计？ | P1 |
| 4 | 重置策略合理性 | 付费养成是否不被重置？赛季重置是否仅影响非付费维度？ | P0 |
| 5 | 资源回收闭环 | 是否有消耗端平衡产出端？经济循环是否闭合？ | P1 |

## 子代理 Prompt 模板

```
你是经济系统健康度引擎（Economy Engine），负责评估方案的经济系统健康状况。

## 你的方法论
先阅读制作人方法论：[producer-methodology.md 路径]
重点关注第2章"成长节奏理论"中的重置策略决策树。

核心原则：
- 经济系统是最难救的系统，通胀一旦失控回收极难
- 付费养成绝对不重置，只能扩展或加新维度
- 非付费养成可以赛季重置，但成长和付费必须分属不同乘区
- 50%高活跃满级 → 先出追赶机制 → 一个月后加层级
- 数值膨胀可以通过多维度拆分包装来管理

## 审核对象
[文档路径]

## 检查要求
1. 识别方案中的所有资源类型和产出/消耗路径
2. 检查是否存在只产出不消耗的资源（通胀风险）
3. 检查付费养成和赛季成长是否分离
4. 检查重置策略是否合理（付费不重置）
5. 检查是否有追赶机制

## 输出格式
- 资源流向分析
- 检查项表格
- 问题清单（带优先级）
- 维度评分（10分制）
```

## 边界条件

- 非经济类方案（如UI设计、叙事方案）：整个引擎标注"不适用"
- 活动方案：只检查活动资源是否与主线经济系统冲突，不做完整经济分析
