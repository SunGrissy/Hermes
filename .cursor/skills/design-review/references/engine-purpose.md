# 引擎1：设计目的检查（Purpose）

## 检查目的

判断方案的设计目的是否清晰、一致、服务目标人群。

> **方法论来源**：制作人审案30秒三层过滤的第一层——"设计目的是否清晰"。
> 制作人原话："设计目的必须能一句话讲明白。越简单的一句话，表示想得越明白。"

## 检查项清单

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|---------|--------|
| 1 | 设计目的清晰度 | 方案是否能用一句话说清核心目的？如果需要两段话才能解释清楚，说明还没想明白 | P0 |
| 2 | 模块服务性 | 方案中的每个模块/子系统是否都在服务设计目的？是否存在"为了有而有"的模块？ | P1 |
| 3 | 目标人群明确性 | 是否明确了服务谁？设计目的是否作用于该人群并达成效果？ | P0 |
| 4 | 宏观适配 | 该方案是否符合整体游戏框架的位置和定位？ | P1 |

## 子代理 Prompt 模板

```
你是设计目的检查引擎（Purpose Engine），负责审核策划方案的设计目的清晰度和一致性。

## 你的方法论
先阅读制作人方法论：[producer-methodology.md 路径]
重点关注第5章"决策框架"中的"审案30秒三层过滤"。

## 审核对象
[文档路径]

## 检查要求
逐项检查以下内容，给出检查项表格（检查项 | 结论 | 说明）：

1. **设计目的清晰度**：尝试用一句话总结方案的核心目的。如果你做不到，标记为P0问题。
2. **模块服务性**：列出方案中的每个模块/子系统，判断其是否服务核心目的。不服务的标记为P1。
3. **目标人群明确性**：方案是否明确了目标玩家？设计是否针对该人群？未明确标记为P0。
4. **宏观适配**：方案在整体游戏框架中的位置是否合理？不适配标记为P1。

## 输出格式
- 检查项表格
- 问题清单（带优先级 P0/P1/P2）
- 维度评分（10分制）
- 如果存在P0问题，生成一个 Gate 类型的决策问题供制作人判断
```

**决策问题**（如有P0）：
[Gate 格式的决策问题]

## 边界条件

- 探索性/实验性方案：允许设计目的模糊，结论标注"低置信度"
- 纯技术方案（如架构重构）：跳过"目标人群"检查项
