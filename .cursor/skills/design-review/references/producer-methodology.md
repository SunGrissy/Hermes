# 制作人方法论

> 本文档由制作人深度访谈提炼而成，是 game-review skill 所有检查引擎的知识源头。

## 1. 设计哲学

**核心尺子**：好游戏设计 = 给玩家创造丰富的情绪体验。

### 六大情绪维度

| 维度 | 说明 |
|------|------|
| 目标感 | 清晰且强烈的目标驱动 |
| 新鲜感 | 探索体验得到满足，包含审美要素 |
| 成长感 | 前中期对数级成长体验，波峰波谷循环 |
| 社交压力 | 适度PVP压力 + 社交协同产生目标感 |
| 叙事性 | 符合受众偏好的故事（女性偏drama，男性偏千面英雄） |
| 随机性 | 操作性条件反射，底层通用情绪刺激 |

宏观结构上也需要设计情绪的波峰波谷，定期给玩家新鲜的东西以塑造期待感。可运用宏观经济学理论激起玩家信心。

## 2. 成长节奏理论

- **波峰波谷循环**：前10分钟就要有"差一点挂了→质变→割草"的体验循环
- **循环周期拉长**：爽感不一定持续放大，但循环周期随时间逐步拉长
- **一年重置周期**：每年一次数值爽感重置，让成长膨胀感可以循环复用

### 重置策略决策树

| 条件 | 策略 |
|------|------|
| 付费养成 | 不重置，只扩展或加新维度 |
| 非付费养成 | 可赛季重置，成长和付费分属不同乘区 |
| 50%高活跃满级 | 触发追赶机制 → 一个月后加层级 |
| 新鲜玩法/体验 | 开一套全新体系 |

### 数值膨胀多维包装（验证有效的模式）

当玩家成长体验到达瓶颈时：新开系统让战力短时间大幅提升，但PVE难度曲线把实际效率拉回稳态。关键是把数值膨胀拆分成多个维度，分别包装成养成线，玩家无法察觉效率回归。利用玩家对成长体验的天然偏好 + 认知盲区。

## 3. 价值排序

**默认优先级**：公平感 > 社交生态 > 爽感 > 留存 > 付费

### 公平感的精确定义

- 不是绝对数值平等，是**感知层面的可接受度**
- P2W游戏中付费变强不等于不公平
- 关键控制点：付费每日增量要在不让非付费玩家感到沮丧的范围内
- 底线保障：免费玩家通过每天劳作，获取价值等价约20-50美金的付费产出
- 实现手段：限度封顶（兵/英雄/加成有上限）+ 阶层分层（生态位内公平竞争）

## 4. 玩家模型

### 四维正交分层

- 付费能力：鲸鱼 / 海豚 / 免费
- 在线活跃：高 / 中 / 低
- 社交参与度：强 / 中 / 弱
- 社交攻击性：强 / 中 / 弱

**优先保护对象**：海豚 + 高活跃 + 强社交 + 中等攻击性（承上启下的中坚层，连接大R和免费玩家）

### 数据驱动分层（对理论模型的增强）

四维正交分层是分析框架，实际玩家的行为分布不一定严格落在预设的格子里。通过线上行为数据聚类，可以发现理论模型未预见的用户类型。

**数据炼化流程**：线上行为日志 → 特征提取 → 聚类分群 → 行为叙事化 → 虚拟用户 Prompt

**与理论模型的关系**：
- 数据聚类的分群结果是"事实"，四维分层是"分析框架"
- 两者不需要完全对齐——数据可能涌现出方法论没预设的群体（如"周末战士""回流候鸟"）
- 当两者不一致时，以数据为准更新认知，而非削足适履让数据匹配理论
- 具体创建流程见 `docs/superpowers/specs/virtual-player-creation-guide.md`

### 关键分层评估对象

| 分层 | 评估重点 |
|------|---------|
| 中坚层（海豚/高活跃/强社交/中攻击） | 是否被保护，是否能承上启下 |
| 大R层 | 付费体验是否匹配投入 |
| 免费层 | 是否有事干，是否感到被孤立 |
| 高攻击性玩家 | 是否有受限机制防止破坏生态 |
| 低活跃玩家 | 是否有追赶/回归路径 |

## 5. 决策框架

### 审案30秒三层过滤

1. 设计目的是否清晰
2. 宏观上是否符合游戏框架
3. 微观上是否给玩家创造目标

### 决策三问

1. 这东西有没有意思，好不好玩
2. 能不能激起目标感和期待值
3. 从宏观循环上是否适配

### 继续优化 vs 推翻重来

- 清晰易懂 + 有好玩的潜质 + 能让人有所期待 → 继续优化
- 以上三者缺失 → 推翻重来

### 决策风格

直觉先行，快速原型，边做边测边改。

### 验证方法

AB test + 只看流失率。穷尽边界值后数据无显著提升 → 砍掉。

## 6. 诊断框架

### 局部问题 vs 结构问题

- 目标感还在但某环节卡住 → 局部体验问题
- 目标感缺失或下降 → 系统结构问题或数值问题

### 关键信号

- **流失首因**：目标感缺失
- **沉默比骂更可怕**：数据变差但社区无人抱怨 = 游戏没有在为玩家创造情绪

## 7. 红线与误区

### 三条红线（触碰即P0）

1. 核心循环不能为短期KPI让步
2. 不能强迫玩家，必须给选择权
3. 不做冗余系统（不服务核心循环的系统）

### 五大误区

| 误区 | 说明 | 检测信号 |
|------|------|---------|
| 堆系统当内容 | 系统多但每个都浅 | 系统数量多但单个深度不足 |
| 数值解决体验问题 | 不去想根因 | 用奖励/数值调整回应体验类问题 |
| 过度参考竞品 | 不考虑自身核心循环 | 大量引用竞品系统但未论证自身需要 |
| 前期过度披露 | 信息过载 | 新手阶段暴露的系统/概念数量过多 |
| 设计给自己玩 | 按策划自己爽的标准设计（**高敏**） | UE不直觉、需要大量文字解释、操作步骤繁琐 |

### 致命缺陷特征

看起来完整但破坏了玩家情绪释放的周期性节奏。

### 高危系统

- 最难救：经济系统（通胀一旦失控回收极难）
- 最怕的伪优化：不符合本地用户消费习惯的逼氪行为

## 8. 失败案例教训

### IP联动调性不符

- 根因：把下沉用户错误理解为接受低俗的用户
- 教训：下沉≠低俗，用户画像认知偏差会导致灾难性决策
- 防护：IP联动前做事前玩家偏好测试；有疑虑时先做出来体验一周再决策

## 9. 设计底线

**一句话**：目标清晰且具备一定程度公平性的设计。
