# 问卷调研分析

基于问卷星等平台导出的 CSV 原始数据，完成问卷设计评析 + 数据分析 + 交叉对比 + 可视化报告。

## 执行流程

```
1. 数据摸底 → 2. 问卷设计评析 → 3. 单卷分析 → 4. 跨版本对比 → 5. 洞察提炼 → 6. 报告产出
```

## 1. 数据摸底

读取 CSV 后先跑基础体检，**不急着分析内容**：

```python
# 必跑指标
- 样本量、字段数
- 答题时长：mean / median / P25 / P75 / min / max
- 速答率（<30s）：>1% 需提示数据质量风险
- 开放题填写率：<40% 说明引导不够或疲劳严重
- 清洗标记分布（若有"清洗数据结果"列）
```

**CSV 字段识别规则**：
- 多选题会展开为多列，格式为 `题干?:选项A`、`题干?:选项B`，空值=未选
- 矩阵评分题同理展开，每列是一个子维度
- `[选项填空]` 后缀列是"其他"选项的填空内容
- 尾部常有元数据列：语言、清洗结果、地理位置、IP、UA 等，分析时排除

## 2. 问卷设计评析

**每份问卷都要评设计**，不是只看数据。评析维度：

| 维度 | 检查项 |
|---|---|
| **量表合理性** | 1-5分是否出现U型分布（两端极化>70%=量表失效）；建议改7点或语义差分 |
| **选项设计** | 单选选项是否互斥完整；多选选项是否混杂了态度与行为；是否有引导性措辞 |
| **漏斗完整性** | 关联问题是否形成漏斗（如：是否离开→离开多久→回流驱动） |
| **题量与疲劳** | 题量 vs 中位时长 vs 慢答率(>300s)；超15题需警惕疲劳 |
| **跨版本锚点** | 是否保留了可纵向对比的标准化题目（NPS、整体满意度等） |
| **信息密度** | 语义选项（完整态度描述）优于纯数字量表，信息量更大 |

输出格式：优缺点各列 3-5 条，附具体建议。

## 3. 单卷分析

### 3.1 满意度/评分题（数值型）

```
必算指标：
- 均分
- Top2 (4+5分占比) / Bot2 (1+2分占比) / Mid (3分占比)
- 分布直方图
```

**分布形态判读**：
- U型（两端高中间低）→ 极化严重，均分失去意义，要分群看
- J型（高分端聚集）→ 天花板效应，需追问"5分到底多满意"
- 正态 → 均分有代表性

### 3.2 多选题

```
必算指标：
- 各选项选择率（选择人数 / 总样本）
- 按选择率降序排列
- 头部集中度：Top3选项的累计占比 vs 长尾
```

**展示方式**：横向柱状图（hBar），不用饼图（多选选项不互斥）。

### 3.3 单选态度题（语义选项 A/B/C/D）

直接算各选项频率，按原选项顺序排列（通常从最正面到最负面）。
展示方式：环形图（doughnut）。

### 3.4 开放题

**关键词主题提取法**：

```python
themes = {
    '爆率/概率': ['爆率', '暴率', '概率', '打不中', '打不到', '难打', '抓不到'],
    '经济压力': ['太贵', '坑钱', '氪金', '充钱', '花钱太', '吃分', '吃金', '经济压力'],
    '免费福利': ['免费', '福利', '白嫖', '多送', '送点'],
    '正面评价': ['好', '不错', '满意', '棒', '赞', '支持', '喜欢'],
    '负面评价': ['垃圾', '差劲', '太差', '骗人', '坑人'],
    # 根据问卷主题追加领域关键词
}
```

注意事项：
- 同一条反馈可以命中多个主题
- 报告时用**占有效反馈数的百分比**，不是总样本百分比
- 关键词需覆盖同义词/错别字（如"爆率"和"暴率"）
- 低分用户(1-2分)的开放题要**单独提取**，识别核心痛点

## 4. 跨版本对比

### 4.1 可直接对比的维度

| 维度 | 前提 |
|---|---|
| 整体满意度均分 | 量表一致（都是1-5分） |
| Top2/Bot2 结构 | 量表一致 |
| 答题质量指标 | 始终可比 |
| 开放题主题频率 | 关键词体系一致 |

### 4.2 需结构化对比的维度（对象不同但性质相同）

典型案例：两版上线的守卫/角色不同，但都有"认知度"多选题。

**不能直接比选项**，要算结构指标：

```
- Top1 认知率：最高单品的绝对值
- Top3 平均认知率：头部集中度
- 极差（最高 - 最低）：均匀度
- ≥30% 认知率的个数：有效传播覆盖
- ≤15% 认知率的个数：被忽视的长尾
```

### 4.3 不可比的维度

- 量表类型不同（数字 vs 语义选项）的题目不能直接比均值
- 不同问题（如 Q5 黄金觉醒 vs Q7 配器体验）即使都是满意度也不能横向比

### 4.4 趋势信号判读

| 现象 | 解读 | 危险等级 |
|---|---|---|
| "希望改善X"减少 + "X很差"不减 | 玩家放弃表达期望（习得性无助） | 高危 |
| 正面评价占比上升 + 满意度均分下降 | 极化加剧，忠诚用户更忠诚但流失面扩大 | 中危 |
| 新功能"无感"最高 + "看别人用"次高 | 覆盖面不足，只惠及头部玩家 | 高危 |
| 均匀度提升 + 头部下降 | 没有明星产品，传播势能弱 | 中危 |

## 5. 洞察提炼原则

遵循制作人思维纪律（参见 `producer-context.mdc`）：

1. **穿透表面指标**：不接受"满意度降了所以体验差了"——要追到具体哪个维度拉低的
2. **看结构再看绝对值**：先看分布形态，再看均值
3. **回到北极星**：每条建议要回答"影响增长效能的哪个变量"
4. **警惕相关≠因果**："视听好评高但满意度降了"不等于"视听投入无效"，可能是其他维度恶化
5. **追问决策本质**：表面问题"认知度低了" → 本质问题"是投放资源不够还是角色本身缺乏记忆点"

## 6. 报告产出

### 交互式 HTML 报告结构

```
标题 + KPI 卡片（3-4个核心数字）
├─ Tab: 对比总览（跨版本共有问题的对比）
├─ Tab: 版本A 详情
├─ Tab: 版本B 详情
├─ Tab: 问卷设计评析
└─ Tab: 行动建议（P0/P1/P2 优先级卡片）
```

### 图表类型选择

| 数据类型 | 图表 | 理由 |
|---|---|---|
| 评分分布 | 环形图 doughnut | 直观看占比结构 |
| 评分对比（两版） | 分组柱状图 bar | 同刻度并排 |
| 多选题 | 横向柱状图 hBar | 标签长，纵向放不下 |
| 多维度评分 | 雷达图 radar | 看均衡性（注意网格可见性） |
| 结构指标 | 数据表格 | 精确数值更重要 |

### 雷达图注意事项

Chart.js 雷达图默认网格线在深色背景下几乎不可见，必须显式配置：

```javascript
scales: {
  r: {
    grid: { color: 'rgba(139,144,165,.3)' },
    angleLines: { color: 'rgba(139,144,165,.3)' },
    pointLabels: { color: '#e2e4ea', font: { size: 13, weight: '500' } },
    ticks: { backdropColor: 'transparent' }
  }
}
```

### 洞察框 (insight) 规范

每个数据 section 后必须跟一个 insight：
- 标注 P0/P1/P2 优先级
- 用 `<strong>` 高亮关键数字
- 先说现象，再说归因，最后给方向性建议
- 避免"数据说明…"这类废话开头，直接切入结论

### 行动建议卡片

按 P0(紧急) / P1(重要) / P2(优化) 分级，每条包含：
- 标题（动词开头，如"优化…"、"恢复…"、"简化…"）
- 1-2 句具体措施（不是"需要改善"，而是"降低高炮倍场最低消耗"）

## 常见陷阱

| 陷阱 | 正确做法 |
|---|---|
| 两版守卫不同却直接比认知率排名 | 比结构指标（极差、Top3均值、长尾数） |
| 量表类型不同却比均值 | 只比 Top2/Bot2 结构，不比绝对均值 |
| 开放题用总样本做分母 | 用有效反馈数做分母 |
| 只看高分用户的正面评价 | 必须单独提取低分(1-2分)用户的开放反馈 |
| 速答数据不清洗直接分析 | <30s 的问卷至少标注风险 |
| 满意度只看均分 | 必须同时看分布形态（U/J/正态） |
| 雷达图/表格网格线看不清 | 深色主题下必须显式配置 grid/angleLines 颜色 |
| 砍掉上版有价值的题目不做对比分析 | 在设计评析中明确指出，建议恢复 |
