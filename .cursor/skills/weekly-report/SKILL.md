# 周报生成 Skill

通过钉钉日志（report）API 提交周报。核心流程：**数据收集 → 逐块确认 → 组装提交**。

## 周报模版结构

模版ID: `153363afcd787a1e1d8f6fc4e87b4cd0`（名称："周报"）

| # | key | sort | type | contentType | 说明 |
|---|-----|------|------|-------------|------|
| 1 | 本周OKR进展回顾（围绕季度OKR，按照3P原则Progress/Problem/Plan回顾） | 0 | 1 | markdown | 主字段，内容最重 |
| 2 | 本周其他工作进展 | 3 | 1 | markdown | 非OKR线工作 |
| 3 | 需协调与帮助 | 5 | 1 | markdown | 阻塞/求助 |
| 4 | 专项工作本周总结 | 6 | 1 | markdown | 沉淀/创新 |
| 5 | 自我评价（5分制） | 7 | 1 | markdown | 1-5分 |
| 6 | 图片 | 8 | 8 | origin | 附件 |
| 7 | 附件 | 9 | 9 | origin | 附件 |

## OKR主字段内容结构

按以下子块组织，每个子块用 **加粗标题** 分隔：

```
**核心PDAU**
第N周日均 MMDD～MMDD 数据概览 + 同比/环比分析

**研发**
线上更新：已开放 / 待开放内容
后续版本：排期清单
重点设计讨论：本周讨论议题

**管线建设**
会议/流程改进（可选，有内容时列出）

**数据工作**
分析诊断和预测：...
数据基建和实验：...

**营销相关**（可选，有内容时列出）
人群包/投放/渠道分析
```

## 生成流程

### Step 1: 数据收集

从以下来源自动拉取本周数据：
1. **老大日报** — `dws report sent --template-name "日报" --start/end`，提取管线/产品/营销/AI实用四类
2. **团队成员日报** — 收件箱 `dws report list` 翻页筛人，`dws report detail` 拉详情（需PAT授权`report:detail`）
3. **共享记忆 hub 报告** — `D:/MyAgents/shared-memory/hub/YYYY-MM-DD.md`
4. **钉钉日历** — `dws calendar event list` 本周事件
5. **Git 巡检** — 本周 commit 变更
6. **Hermes 状态** — 4实例运行状况
7. **用户口述** — 老大补充的内容（最关键）

**多人日报拉取流程：**
1. `dws contact user search --query "姓名"` 取 userId
2. `dws report list` 翻页全量拉取（cursor递增，hasMore判断），按 userId 筛选
3. `dws report detail --report-id <id>` 拉详情（首次需PAT授权，选permanent长期有效）
4. 注意：收件箱 list 是全公司的，数据量可能400+，写脚本批量翻页比手动高效

**版本标签格式：** 日报中版本用 `【0422版本】` 格式，不是 `[0422]`，正则：`[\[【](\d{4})[版本\]]*[\]】]`

**版本进度提取原则：**
- 不要按人按天罗列细节，要提炼每个版本的整体状态（封板/提测/设计中/早期设计）
- 老大的周报写全局视角，不写执行层流水账
- 需要跨人汇总同一版本的所有条目后再归纳

**AI实用统计维度：**
按以下四维统计，不罗列人名：
1. **流程自动化** — tyclaw/koda/agent自动拉数据、发邮件、报警
2. **提效工具** — skill/插件/工具开发，有量化提效数据优先
3. **设计辅助** — AI生图、创意决策、串连boss、文档撰写
4. **工作流重构** — Agent互通、共同记忆库、跨工具链路打通

每周补充亮点和短板各2-3条

**老大日报提取规则：**

从老大日报（`dws report sent --template-name "日报"`）中按四个维度分类提取，去例行会议，只保留实质性产出：

| 维度 | 标记 | 写入子块 |
|------|------|----------|
| 管线 | 【管线】 | 管线建设 |
| 产品 | 【产品】 | 研发-重点设计讨论 |
| 营销/投放 | 【投放】【营销】 | 营销相关 |
| AI实用 | 【AI实用】 | 本周其他工作进展（AI相关部分） |

注意：
- 【组建】类内容（面试、面谈）写入"本周其他工作进展-组织建设"
- 例行会议（脉搏会、管线周会、基础数据会）不写
- 标记词以老大日报实际写法为准，可能变体

**数据工作 - 人员日报映射：**

| 人员 | userId | 提取维度 | 写入子块 |
|------|--------|---------|----------|
| 杨琳 | 2219221169850379 | 分析诊断和预测、数据基建和实验、卡点 | 数据工作-分析/基建/卡点 |
| 程家叙 | 511851105330773806 | 版本日志、策略改动、AB实验 | 数据工作-基建（版本相关）/ 研发-线上更新 |

注意：
- 人员日报有时间范围，先确认createTime落在本周再提取，避免混入上周内容
- 筛选原则：老大的周报写团队级结论，不重复个人日报的流水账细节

### Step 2: 逐块确认

**不要一次性生成完整周报。** 按以下顺序逐块呈现，每块等老大确认/修改后再进下一块：

1. 核心PDAU（需老大提供数据截图或口述）
2. 研发
3. 管线建设
4. 数据工作
5. 营销相关
6. 本周其他工作进展
7. 需协调与帮助
8. 专项工作本周总结
9. 自我评价

每块呈现后问："这块OK？有要改的？" 确认后才进下一块。

**内容原则：**
- 例行会议（脉搏会、管线周会等）不写，只写实质性产出和决策
- 周报不是流水账，要有结论和价值
- 卡点写具体原因，不写模糊一句

### Step 3: 组装提交

所有块确认完毕后：
1. 将内容组装成 `--contents` JSON 数组
2. 展示完整预览给老大最终确认
3. 确认后执行 `dws report create --template-id 153363afcd787a1e1d8f6fc4e87b4cd0 --contents '<json>' --format json`

## contents JSON 格式

```json
[
  {"key":"本周OKR进展回顾（围绕季度OKR，按照3P原则Progress/Problem/Plan回顾）","sort":"0","content":"<markdown内容>","contentType":"markdown","type":"1"},
  {"key":"本周其他工作进展","sort":"3","content":"<markdown内容>","contentType":"markdown","type":"1"},
  {"key":"需协调与帮助","sort":"5","content":"","contentType":"markdown","type":"1"},
  {"key":"专项工作本周总结","列举本周在自己所做的工作上的收获、创新或沉淀","sort":"6","content":"","contentType":"markdown","type":"1"},
  {"key":"自我评价（5分制）","sort":"7","content":"","contentType":"markdown","type":"1"}
]
```

注意：
- 只传 type=1 的文本字段，图片(type=8)和附件(type=9)不传（留空即可）
- shell 传 `--contents` 时外层用**单引号**包住 JSON
- content 中的 `\r\n` 保持原样换行，markdown 格式
