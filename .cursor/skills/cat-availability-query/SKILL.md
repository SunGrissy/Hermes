# 猫姐空闲时间查询与回复

> 查询制作人（猫姐/老大）的钉钉日程，按规则计算空闲时段，并代为回复。

## 什么时候用

- 任何人（包括内部同事、候选人、外部合作方）通过钉钉向满满询问老大什么时候有空。
- 老大自己让满满查空闲时间。

## 什么时候不用

- 老大已经明确指定了时间（如"安排在周三下午2点"）→ 不需要查，直接执行安排。
- 对方问的是"某个具体会议能不能参加"→ 走日程冲突检查，不走本 skill。

## 工作流程

### Step 1: 分类（理解输入）

1. **识别对方身份**：读取 `D:/MyAgents/shared-memory/identity-map.md`，sender_id 命中 → 按表中称呼；未命中 → 中性称呼或不加称呼。
2. **判断 VIP/紧急**：读取 `D:/MyAgents/shared-memory/vip-contacts.md`，sender_id 或花名命中 → VIP。
3. **判断询问类型**：
   - **面试安排**：关键词含"面试"、"面谈"、"候选人"、"简历"、"这个人想约猫姐"等。
   - **紧急事务**：VIP 发出 且 语气含"紧急"、"立即"、"马上"、"今天必须"等。
   - **一般预约**：上述之外。

### Step 2: 研究（获取日程并计算）

1. **查询范围**：
   - 起始：今天 00:00
   - 结束：今天 + 14 天 23:59（超过14天日程不准，不推荐）
   - 命令：`dws calendar event list --start "YYYY-MM-DDT00:00:00+08:00" --end "YYYY-MM-DDT23:59:59+08:00" -f json`

2. **解析已有日程**：从返回结果中提取每个事件的 `start.dateTime` 和 `end.dateTime`，构建**占用时间段**列表。

3. **计算空闲时段**（核心逻辑，必须严格执行）：

   **基础工作时段**（每天）：
   - 上午：09:30 – 12:30（正好 3 小时）
   - 下午：14:00 – 19:00（共 5 小时）
   - 非工作时段不列入可约时段（除非 VIP 紧急情况额外标注）。

   **硬性规则（不可突破）**：
   - 【R1】周一上午全部不可约。
   - 【R2】两个日程之间必须间隔 ≥30 分钟（以前一个日程结束时间为起点，后一个日程开始时间至少在 30 分钟之后）。
   - 【R3】已有日程占用的时段，直接剔除。

   **面试额外规则（仅当询问类型为"面试安排"时生效）**：
   - 【R4】面试不安排在周一下午。
   - 【R5】面试不从 10:00 开始（即 10:00–10:xx 不可约）。
   - 【R6】每天面试 ≤2 个。

   **软性规则（可突破，但必须显式提醒）**：
   - 【R7】每周至少保留 3 个工作时段有完整 3 小时空闲。
     - 上午时段正好 3 小时，若空则算 1 个。
     - 下午时段 5 小时，若连续空闲≥3 小时则算 1 个。
   - 【R8】周五下午尽量不安排面试。

4. **计算步骤**（以单日为单位）：
   - 取基础工作时段（上午、下午）。
   - 扣除已有日程占用的时段。
   - 扣除 R1/R2/R4/R5 等硬性限制时段。
   - 对于面试类型，检查该日已有面试数量，若已达 2 个，当日不再推荐面试时段。
   - 检查软性规则 R7/R8，若不满足，在推荐结果中显式标注。

### Step 3: 输出（组装回复）

**回复结构**：

```
【猫姐未来X天可约时段】

▶ 周X（X月X日）
  上午：XX:XX – XX:XX
  下午：XX:XX – XX:XX

▶ 周X（X月X日）
  上午：XX:XX – XX:XX
  下午：XX:XX – XX:XX

【提醒】
- X
- X
```

**分类回复策略**：

| 类型 | 内容 |
|------|------|
| 一般预约 | 列出所有可约时段。若 R7 不满足，尾部加一句提醒："注意：本周已剩余完整空闲时段不足 3 个，建议优先选择能补足的时段。" |
| 面试安排 | 列出符合面试规则的可约时段。若 R8 触发（周五下午），标注"周五下午尽量不安排，若确需安排请猫姐确认"。 |
| VIP紧急 | 列出正常可约时段 ＋ 额外标注："【紧急插入】若以上时段均不可行，以下时段可强制插入（将突破 XX 规则）：早 XX:XX 前或晚 XX:XX 后。请猫姐确认是否接受。" |

**语气**：
- 对内部同事：简洁、不客套、带时段直出。
- 对外部/候选人：温和、有礼貌、不透露过多内部规则细节。
- 禁止说"猫姐没空"，只说"猫姐X日可约时段是..."。

## 判断框架

**如何判断是否需要跟老大确认**：
n
- 正常情况下，skill 直接代回，不打扰老大。
- 必须升级给老大确认的情况：
  1. VIP 紧急事务且突破了软性规则（R7/R8）。
  2. 询问的时间范围超出未来 7 天（超出部分不准）。
  3. 查询结果为"未来 7 天内无任何可约时段"。

**如何判断是否触发本 skill**：
- 消息中含"猫姐"或"老大"或"孙懿"，且含"有空"、"方便"、"约"、"面试"、"时间"等词。
- 如果消息是老大自己发的"查查我什么时候有空"→ 同样触发。

## 做不到什么（诚实边界）

- 无法读取老大设置为"私密"的日程（钉钉日历隐私设置），只能以公开日程为准。
- 无法判断老大当天的主观状态（如"虽然日程空但老大今天不想见人"）。
- 无法预知未建立的日程（某些会议可能还没录入钉钉日历）。
- 超过未来 14 天的查询结果不准确，skill 不推荐超过 7 天的时段。
- 30 分钟缓冲是硬性规则，不因"前一个会议只有 15 分钟"而缩短。
