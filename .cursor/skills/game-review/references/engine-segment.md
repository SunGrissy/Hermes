# 引擎5：玩家分层影响评估（Segment）

## 检查目的

评估方案对各正交维度玩家的影响，确保中坚层（承上启下的海豚层）被保护。

> **方法论来源**：制作人玩家模型——"四维正交分层，优先保护海豚+高活跃+强社交+中攻击性。"
> 保护原因："因为他们是一个承上启下的阶层。"

## 四维正交分层

| 维度 | 分层 |
|------|------|
| 付费能力 | 鲸鱼 / 海豚 / 免费 |
| 在线活跃 | 高 / 中 / 低 |
| 社交参与度 | 强 / 中 / 弱 |
| 社交攻击性 | 强 / 中 / 弱 |

## 关键评估对象

| # | 分层组合 | 评估重点 | 严重度（被忽略时） |
|---|---------|---------|------------------|
| 1 | 中坚层（海豚/高活跃/强社交/中攻击） | 是否被保护，体验是否正面 | P0 |
| 2 | 大R层（鲸鱼/任意活跃/任意社交） | 付费体验是否匹配投入 | P1 |
| 3 | 免费层（免费/任意活跃） | 是否有事干，是否感到被孤立 | P1 |
| 4 | 高攻击性玩家 | 是否有受限机制防止破坏生态 | P1 |
| 5 | 低活跃玩家 | 是否有追赶/回归路径 | P2 |

## 虚拟用户档案接入（可选增强）

当 `virtual-players/` 目录下存在数据炼化的虚拟用户档案时，Segment 引擎的评估质量可以显著提升：

| 模式 | 数据源 | 评估方式 |
|------|--------|---------|
| 基础模式（无虚拟用户） | 制作人方法论的四维分层 | AI 逻辑推演各分层影响 |
| 增强模式（有虚拟用户） | 数据聚类的真实行为画像 | 逻辑推演 + 虚拟用户行为模拟交叉验证 |

**增强模式下的额外检查**：
1. 将虚拟用户档案的"对应方法论分层"字段与 5 个关键评估对象对齐
2. 如果聚类结果中出现了方法论未预设的用户类型，标注为"数据发现的新分群"，交给制作人判断是否纳入评估
3. 引用虚拟用户档案中的行为叙事来佐证分层影响判断（如："社交海豚的画像显示流失敏感点是公会生态恶化，该方案的 XX 机制可能触发此条件"）

详见 [virtual-player-integration.md](virtual-player-integration.md) 的完整集成规范。

## 子代理 Prompt 模板

```
你是玩家分层影响评估引擎（Segment Engine），负责评估方案对不同玩家群体的影响。

## 你的方法论
先阅读制作人方法论：[producer-methodology.md 路径]
重点关注第4章"玩家模型"。

核心原则：
- 玩家分层是四维正交的，不能用单一维度简化
- 中坚层（海豚/高活跃/强社交/中攻击）是承上启下的桥梁，优先保护
- 中坚层流失 → 大R没人配合 + 免费玩家没有组织者 → 生态塌方

## 虚拟用户档案（如可用）
[列出 virtual-players/ 目录下的档案文件路径]
请读取每个档案的"行为画像"和"对应方法论分层"字段，
用真实行为数据替代纯逻辑推演来评估分层影响。
如果档案中的分群与方法论预设的5个评估对象不完全对应，标注差异。

## 审核对象
[文档路径]

## 检查要求
1. 对5个关键分层组合分别评估方案影响（正面/负面/无影响）
2. 重点检查中坚层是否被保护
3. 检查是否存在某个分层被完全忽略
4. 标注可能的生态风险
5. （增强模式）引用虚拟用户行为画像佐证判断
6. （增强模式）标注数据分群与方法论分层的差异

## 输出格式
- 分层影响矩阵
- 问题清单（带优先级）
- 维度评分（10分制）
- （增强模式）虚拟用户佐证摘要
```

## 边界条件

- 单人PVE方案：社交参与度和攻击性维度标注"不适用"
- 新手引导方案：所有分层简化为"新玩家"，不做细分
- 虚拟用户档案为人工编写版时：在报告中标注"佐证来源：人工编写画像（非数据炼化）"，降低置信度
