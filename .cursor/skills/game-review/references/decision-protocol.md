# 直觉层决策问题协议

## 概述

AI完成逻辑层检查后，不直接给最终结论，而是生成结构化决策问题交给制作人判断。这是双层协作的核心机制——**AI做逻辑，人做直觉**。

## 决策问题分类

### Gate（门控）

**定义**：AI无法替代人判断的核心问题。
**触发**：涉及"好不好玩"、"目标感是否清晰"、"节奏对不对"等需要直觉的判断。
**行为**：必须等人回答才能继续。

**典型场景**：
- Purpose 引擎发现设计目的可以多种理解 → 问制作人哪种理解是对的
- Rhythm 引擎检测到情绪平原 → 问制作人这段体验的目标感是否足够

### Flag（标记）

**定义**：AI发现了逻辑问题，请人确认是否真的是问题。
**触发**：引擎检测到可能的违规，但AI无法确定是有意为之还是真的有问题。
**行为**：人可以推翻AI结论。

**典型场景**：
- RedLine 引擎发现一个系统不服务核心循环 → 问制作人是否有意为之
- Value 引擎检测到付费设计可能影响公平感 → 问制作人是否认同

### Sense（直觉）

**定义**：纯直觉判断，无法量化。
**触发**：涉及"有没有意思"、"这个体验对不对"等完全依赖经验的判断。
**行为**：人的回答直接记录为制作人裁决，不做二次质疑。

**典型场景**：
- 成长节奏的波峰波谷间隔是否"感觉对"
- 某个系统的 UE 是否"清晰易懂"
- 虚拟用户的行为预测是否符合你对真实玩家的直觉

## 生成规则

1. **每轮最多3个问题**——不一次性轰炸，优先问影响最大的
2. **优先级顺序**：先 Gate → 后 Flag → 后 Sense
3. **提供选项**：尽可能给A/B/C选项，降低决策负担
4. **附带事实依据**：每个问题附上AI检测到的具体事实，人只需判断"是否认同"
5. **不重复提问**：同一个问题不同引擎都发现了，合并为一个决策问题

## 决策问题模板

### Gate 模板

```markdown
## 🔒 Gate 决策 #N

**引擎来源**：[引擎名称]
**检测事实**：[AI发现的具体事实，引用方案原文]
**问题**：[需要人判断的问题]

- A) [选项A — 通常是"问题存在，需要修改"]
- B) [选项B — 通常是"这是有意设计，不需要改"]
- C) 不确定，需要做原型/AB test验证
```

### Flag 模板

```markdown
## 🚩 Flag 标记 #N

**引擎来源**：[引擎名称]
**检测事实**：[AI发现的逻辑问题]
**AI判断**：[AI认为这是什么问题，严重度]
**需要确认**：你认同这是一个问题吗？

- A) 认同，需要修改
- B) 不认同，这是有意为之（请说明原因）
```

### Sense 模板

```markdown
## 💡 Sense 直觉 #N

**引擎来源**：[引擎名称]
**背景**：[相关的方案内容摘要]
**问题**：[需要直觉判断的问题]

请直接给出你的判断。
```

## 人回答后的AI行为

| 人的回答 | AI下一步 |
|---------|---------|
| 认同问题存在 | 自动生成优化建议（逻辑层能做的部分） |
| 不认同，给出理由 | 记录为"制作人裁决"，在报告中标注理由 |
| 不确定 | 标记为"待验证项"，建议做原型或AB test |
| 选择了某个选项 | 按选项方向继续推进分析 |

## 虚拟用户触发的决策问题

当虚拟用户行为测试的结果与引擎结论产生矛盾时，自动生成决策问题：

### Segment vs 虚拟用户矛盾 → Flag

**触发条件**：Segment 引擎判定某分层影响为正面，但该分层对应的虚拟用户在行为测试中预测会放弃/流失。

```markdown
## 🚩 Flag 标记 #N

**引擎来源**：Segment + 虚拟用户交叉验证
**检测事实**：
- Segment 引擎判定：方案对 [分层] 影响为 ✅ 正面
- 虚拟用户 [标签] 反馈：[具体行为预测，如"第三天不会再玩，因为…"]
**AI判断**：两者矛盾，可能是 Segment 的逻辑推演遗漏了具体行为场景。P1 级别。
**需要确认**：你认为哪个判断更接近真实情况？

- A) Segment 引擎判断更准——虚拟用户画像可能不够准确
- B) 虚拟用户反馈更可信——Segment 的逻辑推演忽略了这个场景
- C) 不确定，需要做原型验证
```

### 虚拟用户发现新风险 → Flag

**触发条件**：虚拟用户指出了 6 大引擎都未覆盖到的问题。

```markdown
## 🚩 Flag 标记 #N

**引擎来源**：虚拟用户行为测试
**检测事实**：虚拟用户 [标签] 提出了一个 6 大引擎未检测到的风险：[具体内容]
**AI判断**：这可能是引擎检查清单的盲区。建议评估是否需要补充到对应引擎的检查项中。
**需要确认**：你认为这是一个真实的风险吗？

- A) 是，需要在方案中处理
- B) 不是，虚拟用户的反应不符合真实玩家行为
- C) 可能是，但优先级不高，记录为 P2 待办
```

### 多个虚拟用户一致预测流失 → Gate

**触发条件**：≥2 个虚拟用户在行为测试中预测会因该方案放弃游戏。

```markdown
## 🔒 Gate 决策 #N

**引擎来源**：虚拟用户行为测试
**检测事实**：
- [用户A标签]：[放弃原因]
- [用户B标签]：[放弃原因]
**问题**：多个典型用户预测会因此方案流失。这是方案的根本问题，还是虚拟用户画像不够准确？

- A) 方案确实有问题——需要重新审视核心设计
- B) 虚拟用户画像不准——实际玩家不会这样反应
- C) 不确定，需要做小范围玩家测试验证
```

## 多轮决策

如果第一轮3个问题回答后，仍有重要的未决问题：
1. 基于第一轮回答，更新分析结论
2. 生成第二轮决策问题（仍然≤3个）
3. 重复直到所有关键判断点都已覆盖

一般不超过3轮。超过3轮说明方案问题过多，建议推翻重来。
