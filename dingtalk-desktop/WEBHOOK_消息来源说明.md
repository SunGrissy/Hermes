# 小秘书提醒 · 消息是谁发的？

同一条机器人（关键词：小秘书提醒）会由多个功能发消息，用下面方式区分。

## 一、看消息内容里的来源标签（推荐）

发出去的正文末尾或首句会带**来源标签**，点开消息看完整内容即可：

| 来源标签 | 谁发的 | 触发方式 |
|----------|--------|----------|
| **· 状态检查** | 上班啦状态检查 | 在助理通知群发「上班啦」 |
| **文档预审完成** / **收到文档链接，正在读取并预审** | 文档预审 (doc_review) | 在助理通知群发文档链接后发「预审」 |
| **简历初筛通过/待定/不通过** | 简历初筛 (resume_screen) | 招聘群内有人发 PDF 简历 |
| 备忘确认 / 今日关注 / 到期日已调整 / done: memo | 备忘 (memo_tracker) | 在助理通知群发「备忘」「完成 #n」「今天关注啥」「1、2推到明天」等 |
| 日报摘要 / 版本状态 | 日报/版本摘要 | 定时或脚本触发 report_digest / version_digest |

若**只看到「小秘书提醒」四个字**、没展开正文：多半是钉钉只显示了标题，点进该条消息即可看到完整内容和来源。

## 二、事后查：看 daemon 控制台日志

运行 daemon 的终端里会有发送前后的日志，按时间对一下即可：

- **状态检查**：`[skill_router] push: 上班啦 -> 已执行状态检查并推送` 或 `poll: 上班啦 -> ...`
- **文档预审**：`doc_review ...`、`预审指令触发`、`文档预审完成`
- **备忘**：`push: 备忘已收录`、`push: 完成指令已处理`、`push: 今日关注已回复`、`push: 备忘延期已处理`
- **简历**：`发现新简历`、`处理完成`

日志路径：daemon 标准输出；若重定向了则看对应日志文件。

## 三、当前已加「来源标签」的模块

- **状态检查**：footer 为 `※ 小秘书提醒 · 状态检查`，方便一眼认出是「上班啦」触发的。

其他模块（预审、备忘、简历等）文案里已有明显业务用语，可按上表对号入座。
