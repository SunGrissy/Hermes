# 发「备忘」「预审」没有回应 — 排查说明

发助理通知群里的「备忘」「预审」「上班啦」等指令后没有回复，通常是**消息没有进到 daemon**，或 **Frida 未正确附加**。按下面顺序自检。

---

## 1. 看 daemon 启动日志（最重要）

运行 daemon 的窗口里应有类似输出：

- **`Frida 已附加，CEF 就绪`** → 附加成功，可以收「发送」消息并秒级触发。
- **`SkillRouter 已启动 (助理群推送=秒级)`** → 说明有推送队列，你**发**出的「备忘/预审」会走推送路径。
- 若出现 **`初始附加失败，watchdog 将自动重试`** 且没有 **`助理群推送=秒级`** → 当前只有轮询（约 20 秒一次），且 /fetch 也可能失败，容易收不到消息。

**结论**：若日志里**没有**「助理群推送=秒级」，多半是 Frida 未附加或监听未启动，发备忘/预审不会触发。

---

## 2. 确认钉钉和助理群

- 发「备忘」「预审」的群必须是 **digest_config.json** 里配置的助理群：
  - `memo_tracker.group_cid` 或 `notify_target`（一般为同一群，如 `73216314617`）。
- 若你换了一个群发，cid 对不上就不会触发。

---

## 3. 自检接口（可选）

在 PowerShell 里执行（把 `73216314617` 换成你配置的助理群 cid）：

```powershell
# 健康与版本
Invoke-RestMethod -Uri "http://127.0.0.1:19200/api/health" -Method Get

# 拉该群最近 5 条消息（需 Frida 已附加且 CEF 可用）
$body = '{"cid":"73216314617","count":5}'
Invoke-RestMethod -Uri "http://127.0.0.1:19200/fetch" -Method POST -Body $body -ContentType "application/json; charset=utf-8"
```

- **/api/health** 正常 → daemon 在跑。
- **/fetch** 若返回 `success: true` 且 `messages` 有数据 → 能拉到该群消息，轮询路径应能处理历史消息。
- **/fetch** 若返回 `success: false` 或 `error: 未找到有 listMessage API 的 browser` 等 → Frida/CEF 未就绪，**发新消息也不会进推送**，需要解决附加/CEF 后再试。

---

## 4. 常见原因与处理

| 现象 | 可能原因 | 建议 |
|------|----------|------|
| 日志里没有「助理群推送=秒级」 | Frida 未附加或监听未启动 | 重启钉钉、再启 daemon；或等 watchdog 自动重试后看是否出现「Frida 已附加」 |
| 钉钉刚升级 | Hook 偏移/接口变化 | 等 daemon 更新适配，或暂时用轮询（约 20 秒延迟） |
| /fetch 报错「未找到 browser」 | 当前窗口不是会话窗口或 CEF 未注入 | 在钉钉里打开一次**助理通知群**会话，再试 /fetch |
| 有推送但从不触发 | 群 cid 与配置不一致 | 核对 digest_config 里 `memo_tracker.group_cid` / `notify_target` 是否为该群 cid |

---

## 5. 代码侧已做的加固

- daemon 里 `_memo_callback` 的 cid 比较已改为 `str(rec.get('cid')) == str(_memo_cid)`，避免类型不一致导致漏进队列。
- 若 `memo_tracker.group_cid` 未配置，会回退使用 `notify_target` 作为助理群 cid，保证有配置时就能收消息。

若按上面检查仍不触发，把 **daemon 启动时的几行日志**（是否出现「Frida 已附加」「助理群推送=秒级」）和 **/fetch 的返回**（或报错）贴出来，便于继续排查。
