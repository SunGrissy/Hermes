# 版本汇总与管线推送（钉钉）

本文说明 **版本状态汇总（VersionDigest）** 与 **管线专项 / 定时管线提醒** 两条推送链路：入口、配置、正文来源、Webhook、@ 人规则与定时任务。

---

## 1. 功能对照

| 项目 | 版本汇总 VersionDigest | 管线定时提醒（auto-scheduled） |
|------|------------------------|--------------------------------|
| **典型用途** | 定时/手动把多版本状态摘要推到多个群（PMO、助理、PLD 等） | 按「规划窗口」筛版本，对**每个命中版本**各推一条专项状态 |
| **入口脚本** | `version_digest.py`（常被 `run_version_digest.ps1` 调用） | `run_pipeline_notify_scheduled.ps1` → `py _push_versions_webhook_at_dm.py --auto-scheduled` |
| **正文拼装** | 与 PM 专项一致：`pm-system` 的 `render_version_status_markdown` + 管线节点 checklist / 内部清单后缀；文末可带 [查看版本详情] 固定链接 | **相同渲染链**；每个版本单独一条 Markdown |
| **版本怎么选** | `GET /api/dashboard` 活跃版本，经 `version_digest_limit`（如 3）截断 | `--auto-scheduled`：**`phase` 非 released**、**管线发版节点未完成**、**非 demand_pool**；且 **`pipelineDdls.planning` 有值**，且该日期距今 **≤28 天**（含已过期）。**不用 startDate 推算**，避免与界面「规划截止」不一致；无命中则**不推送** |
| **Webhook 从哪来** | 见下文「版本汇总：Webhook 与 @」 | 每个版本上的 **`progressNotifyWebhooks`**；若为空则用 **`webhook_config.json` 的 `default`** |
| **@ 谁** | 按 **`webhook_config` 键名** + **`digest_config.version_digest_webhook_at`** 分群配置 | 单条消息内：**PM → APM → PLD → PLE → PLT 前/后端 → PLQA**（去重，需 PM `users` 里有钉钉手机号） |
| **计划任务（示例）** | 任务名 **`VersionDigest`**，常见 **每日 15:00**（`register_version_digest_task.ps1`） | **`MyAgents_PipelineNotify_0915`**、**`MyAgents_PipelineNotify_1945`**：**周一至周六** **09:15** / **19:45**（周日不跑；若本机仍为旧名 `_1615`，请重跑注册脚本以改名并去重） |
| **其它触发** | 助理群「版本咋样了」、`skill_router` 调 `run_version_digest_send` | 手动：`py _push_versions_webhook_at_dm.py`；`--only 版本名`；默认列表「五一版 / 五月中 / 0401」等见脚本 `_default_jobs` |

## 2. 版本汇总（VersionDigest）

### 2.1 依赖

- PM 服务可达：`digest_config.json` 中 `pm_system_url`、`pm_system_api_key`。
- 接口：`/api/dashboard`、`/api/data`、`/api/internal/version-checklist-blocks` 等（与 `_push_versions_webhook_at_dm` 同源）。
- 钉钉机器人：消息类型为 Markdown，标题侧需满足群内机器人「自定义关键词」（如 **小秘书提醒**），与现有机器人配置一致。

### 2.2 Webhook 与 @（推荐：键名，不靠 URL 顺序）

1. **`webhook_config.json`**  
   为每个群机器人配置 **稳定键名**，例如：
   - `version_digest_pmo` — 😈PMO 根据地  
   - `version_digest_assistant` — 🐱助理通知  
   - `version_digest_pld` — PLD 办公室等  

   保留键 **`version_digest`** 可与 PMO 同 URL，兼容旧引用。

2. **`digest_config.json`**

   - **`version_digest_webhook_keys`**：字符串数组，**发送顺序 = 数组顺序**，值为 `webhook_config` 里的键。  
   - **`version_digest_webhook_at`**：对象，**键与上面相同**，值为 `@` 策略：
     - `pm_apm`：仅圈 **PM**（`default_pipeline_pm_user_id`）+ **APM**（`default_pipeline_apm_user_id`）
     - `none`：正文不 @ 任何人
     - `ops_team`：圈 **`version_digest_ops_member_names`** 中能在 PM `/api/data` → `users` 里按**姓名**匹配到的人员（`dingtalk_mobile` / `phone`）

   - **兜底**：若未配置 `version_digest_webhook_keys` 或键在 `webhook_config` 中缺失，则仍使用 **`version_digest_webhooks` 直填 URL**；此时 `@` 可用旧字段 **`version_digest_webhook_at_policy` 数组**与 URL **下标对齐**，或缺省为「管线全角色 @」（与专项推送并集一致）。

### 2.3 手动执行

```powershell
cd dingtalk-desktop
py version_digest.py              # 真实推送
py version_digest.py --dry-run    # 只打印，不发
```

### 2.4 注册定时任务（每日 15:00 示例）

管理员 PowerShell 执行：`register_version_digest_task.ps1`（详见脚本内说明）。任务名一般为 **`VersionDigest`**。

## 3. 管线专项与定时管线提醒

### 3.1 脚本：`_push_versions_webhook_at_dm.py`

- **`--auto-scheduled`**：从 `digest_config` 读 PM 地址，拉全量版本后按 **规划 DDL 窗口**筛选，对**每个**命中版本渲染并推送；无命中则进程退出 0、不发钉钉。  
- **管线节点待办正文**：即使已调用 PM 的 `/api/internal/version-checklist-blocks`，也会用**本机** `pm-system` 里的 `render_pipeline_node_checklists_markdown` **覆盖**接口里的「管线节点待办」块，避免服务端未同步代码时标题仍显示旧的「阻塞/关注」合计。  
- **未加 `--auto-scheduled`**：默认推「五一版 / 五月中 / 0401」等（见 `_default_jobs`），或用 **`--only 名称1,名称2`** 指定版本。  
- **报告**：可在 `logs/` 下生成报告文件（如 `_pipeline_scheduled_report.md`），便于核对是否 OK。

### 3.2 定时包装：`run_pipeline_notify_scheduled.ps1`

- 调用：`py _push_versions_webhook_at_dm.py --auto-scheduled --report "_pipeline_scheduled_report.md"`（报告名以脚本为准）。  
- 日志：`logs/pipeline_scheduled_YYYYMMDD.log`。

### 3.3 注册 Windows 计划任务

- **无需管理员（推荐）**：`register_pipeline_notify_task.ps1`  
  - 任务：**`MyAgents_PipelineNotify_0915`**、**`MyAgents_PipelineNotify_1945`**（会尝试删除旧任务名 **`MyAgents_PipelineNotify_1615`**）  
  - 时间：**周一至周六** **09:15**、**19:45**（**周日不跑**）  
- **需最高权限运行**：`register_pipeline_notify_schtasks.ps1`（`schtasks`，逻辑与上类似，见脚本）。

## 4. 排错简要

| 现象 | 可检查项 |
|------|----------|
| VersionDigest 导入失败 | `pm-system` 需在 `sys.path` 下；缺模块时看 `_push_versions_webhook_at_dm` 依赖的 `app.services.*` |
| 某群没 @ 到人 | `version_digest_webhook_at` 是否对应键；`users` 是否含 `dingtalk_mobile`；`ops_team` 姓名是否与 PM 一致 |
| 管线定时从未推 | `--auto-scheduled` 是否筛到 0 个版本；`progressNotifyWebhooks` 与 `webhook_config.default` 是否为空；看 `logs/pipeline_scheduled_*.log` |
| 计划任务未跑 | 任务计划程序里是否启用；是否周日（管线任务周日不触发） |

## 5. 相关文件一览

| 文件 | 作用 |
|------|------|
| `version_digest.py` | 版本汇总拉数、拼装、按群 @、推送 |
| `run_version_digest.ps1` | 包装执行 `version_digest.py` |
| `_push_versions_webhook_at_dm.py` | 管线专项 Markdown、批量/定时推送 |
| `run_pipeline_notify_scheduled.ps1` | 定时调用 `--auto-scheduled` |
| `webhook_config.json` | 各场景机器人 URL 的**键名**（含 `version_digest_*`、`default`） |
| `digest_config.json` | PM 地址、API Key、`version_digest_webhook_keys`、`version_digest_webhook_at`、运营姓名列表等 |
| `register_version_digest_task.ps1` | 注册 VersionDigest 定时任务 |
| `register_pipeline_notify_task.ps1` | 注册管线 Mon–Sat 定时任务 |
| `register_pipeline_notify_schtasks.ps1` | 管理员版注册管线任务 |
