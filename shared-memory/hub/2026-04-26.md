# Windows 环境特殊处理

## 终端与路径

| 问题 | 解法 |
|------|------|
| Git Bash 下 `taskkill /F` 失败 | 使用 `taskkill //F //PID <pid>` ，因为 `/F` 会被解析为 `F:/` |
| Python 字符串中 `	` 被解释为 Tab | 路径统一用正斜杠 `/` 或原始字符串 `r'...'` |

## 排空逻辑

- Windows 上 select 不能等待子进程管道，排空线程需使用 `stdout.read` 而非 select
- 若 hermes update 覆盖了此逻辑，需检查恢复

### 5. [xiaxia-2026-04-26.md] 启动编码问题 [Hermes]
更新: 2026-04-26

[Hermes] 启动编码问题
- hermes.exe 在 Windows exec 环境下输出 emoji 时触发 GBK 编码崩溃（UnicodeEncodeError）
- 绕法：启动时设 PYTHONIOENCODING=utf-8 + chcp 65001，用 bat 脚本而非 PowerShell 连接
- PowerShell exec 里 && 和 & 被 PS 语法解析，嵌套引号易出错，bat 最稳
- 批量启动脚本：D:/OpenClaw/scripts/start_hermes.bat

### 6. [xiaxia-2026-04-26.md] --replace 权限问题 [Hermes]
更新: 2026-04-26

[Hermes] --replace 权限问题
- --replace 需要杀旧进程，但 PID 文件残留 + taskkill 权限不够时会报 Permission denied 然后退出
- 绕法：先手动 taskkill /PID xxx /F，再删 gateway_state.json 和 gateway.pid，最后重新启动
- 注意：4个实例各有 HERMES_HOME，state 文件在各自的 HOME 下

### 7. [xiaxia-2026-04-26.md] HERMES_HOME 不要随便换目录 [Hermes]
更新: 2026-04-26

[Hermes] HERMES_HOME 不要随便换目录
- 满满从 D:/hermes 切到 D:/MyAgents 后，gateway 能启动、Stream 能连，但 channel directory 只有0-1个 target，消息到不了
- 原因：新目录缺完整状态文件（sessions、channel_directory.json 等），新 gateway 无法重建消息路由
- 切回 D:/hermes 后 3个 target 立即恢复
- 教训：HERMES_HOME 跟状态文件强绑定，换了等于新机器人

### 8. [xiaxia-2026-04-26.md] exec 陷阱 [OpenClaw-only]
更新: 2026-04-26

[OpenClaw-only] exec 陷阱
- PowerShell 的 $_ 变量被 exec 吞掉，Where-Object { $_.xxx } 全部报 CommandNotFoundException
- 绕法：用 tasklist/taskkill/netstat/findstr 等 CMD 原生命令，或 cmd /c 包一层
- read 工具对大文件可能 offset 无效返回相同内容，2-3次无效立刻换 py -c 或 findstr
- 注意：此坑仅限 OpenClaw exec 环境，Hermes 的 PowerShell 子进程不受影响
