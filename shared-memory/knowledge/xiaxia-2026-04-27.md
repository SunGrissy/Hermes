## §1 钉钉群聊引用消息结构发现

**发现者**：虾叔（AgentXia）
**日期**：2026-04-27
**影响**：所有使用钉钉 Stream API 的 Agent（Hermes + OpenClaw）

### 问题
群聊中用户引用一条消息 @机器人，机器人读不到引用内容。私聊也有同样问题。

### 根因
钉钉 Stream API 下发的消息事件中，引用消息数据放在 `text.extensions` 字段内，而非 `text` 顶层。

**实际数据结构：**
```json
{
  "text": {
    "content": "用户新打的话",
    "extensions": {
      "isReplyMsg": true,
      "repliedMsg": {
        "createdAt": 1777280439590,
        "senderId": "$:LWCP_v1:$xxx",
        "msgType": "text",
        "msgId": "msgxxxxx==",
        "content": {
          "text": "被引用的原消息内容"
        }
      }
    }
  }
}
```

另外 `message.extensions.originalMsgId` 也包含被引用消息的 ID。

**注意**：`text.isReplyMsg`（顶层）在群聊和私聊中均为空/不存在，必须检查 `text.extensions.isReplyMsg`。

### 已修复
1. **Hermes** `gateway/platforms/dingtalk.py` - `_extract_text` 方法已增加 `text.extensions` 路径提取
2. **OpenClaw** `dingtalk-connector/src/core/message-handler.ts` - `extractMessageContent` 的 text/richText/reply 三个 case 已增加 `extensions` 路径检查
3. 验证通过：妙妙(Hermes) + 小马(OpenClaw) 均已确认群聊引用消息可读

### 修复原则
- 纯增量式：原有 `text.isReplyMsg` 检查保留，新增 `text.extensions.isReplyMsg` 检查作为补充
- 没有引用消息时行为完全不变，不影响非引用场景

## §3 OpenClaw 钉钉 Watchdog 定时器

**日期**：2026-04-27
**修改者**：虾叔（AgentXia）
**影响**：OpenClaw dingtalk-connector

### 问题
OpenClaw 在钉钉里处理长任务时，AI Card 长时间不更新，用户以为卡了。OpenClaw 原生 tool-progress preview 不支持钉钉（仅支持 Discord/Slack/Telegram/Mattermost）。dingtalk-connector 是插件 channel，schema 不接受 blockStreaming 字段。

### 方案
在 `reply-dispatcher.ts` 加 watchdog 定时器：
- 每60秒检查一次，如果 AI Card 存在且模型没有新输出，更新 AI Card 显示"还在处理中"
- 模型有新输出时（onPartialReply 触发）重置计时
- onIdle/onError/onCleanup 时清除定时器
- 超过1分钟后显示已等待分钟数

### 修改文件
`D:\OpenClaw\extensions\dingtalk-connector\src\reply-dispatcher.ts`

### 待验证
需长任务场景触发验证（简单对话响应快不会触发 watchdog）
