## 踩坑：PowerShell exec 里 && 和 || 不可用
- 坑：OpenClaw exec 工具走 PowerShell，`&&` 被解析为后台运算符 `&` + 语法错误，`||` 根本不认。多条 `set A=1 && set B=2 && start xxx` 全部报错
- 绕法：写 `.bat` 脚本文件，再 `cmd /c "路径.bat"` 执行
- 记到：各 Agent 自己的 TOOLS.md
- 来源：虾叔

## 踩坑：OpenClaw gateway restart 不支持 --workdir
- 坑：`openclaw gateway restart` 没有 `--workdir` 选项，只能重启默认实例（虾叔 18789）。小马（OpenClaw2，18790）要重启得手动来
- 绕法：`taskkill /PID <pid> /F` 杀进程 → 用 bat 脚本设环境变量后 `start` 新进程
- 小马启动脚本：`D:\OpenClaw2\start_gateway.bat`
- 记到：各 Agent 自己的 TOOLS.md
- 来源：虾叔

§3
## 踩坑：DeepSeek V4 Flash reasoning 模式报 400
- 坑：DeepSeek V4 Flash 配置 `reasoning: true` 后，多轮对话 OpenClaw 回传消息时没带 `reasoning_content` 字段，API 返回 400：`The reasoning_content in the thinking mode must be passed back to the API.`
- 绕法（OpenClaw 自定义 provider）：`reasoning: false` 关闭 thinking，或者用 DeepSeek 内置插件（插件会自动处理 reasoning_content 回传和 thinking 参数）
- 影响：小马（deepseek-v4-flash）已修复，其他 Agent 如果也用 DeepSeek reasoning 模式需注意
- 来源：虾叔

§4
## 踩坑：OpenClaw DeepSeek 内置插件 vs 自定义 Provider 打架
- 坑：OpenClaw 内置 DeepSeek 插件需要 `DEEPSEEK_API_KEY` 环境变量才能注册模型。光写 `plugins.entries.deepseek.enabled: true` 不够，模型仍然报 "Unknown model: deepseek/deepseek-v4-flash"
- 坑2：插件 schema 不接受 `apiKey` 和 `env` 字段，不能在 plugins.entries.deepseek 里直接传 key
- 坑3：`openclaw onboard --auth-choice deepseek-api-key` 会把 gateway port 改回默认 18789，deepseek 插件反而被设为 enabled:false
- 坑4：`.env` 文件放 `$OPENCLAW_STATE_DIR/.env` 不一定被 gateway 读取
- **正确方案（二选一）**：
  1. **走插件**：设好 `DEEPSEEK_API_KEY` 环境变量（全局或 `.env`），让插件自动注册模型和处理 reasoning_content 回传
  2. **走自定义 provider**：`models.providers.deepseek` 直连 API + `models.mode: "replace"` + 禁用插件 + 直接写 apiKey
- **不要混用**：同时启用插件又定义自定义 provider 会导致模型注册冲突
- DeepSeek V4 正确参数（官方文档）：`reasoning: true`, `contextWindow: 1000000`, `maxTokens: 384000`
- 小马当前用方案2：`D:\OpenClaw2\openclaw.json`
- 来源：虾叔
