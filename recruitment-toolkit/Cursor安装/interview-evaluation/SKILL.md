# 面试评价生成

基于面试记录（文字转写、笔记、或口述要点），生成一份结构化的面试评价报告。报告需覆盖：评分、亮点、风险、逐条复盘、综合判断、证据索引。

## 何时使用

- 用户面试结束后，提供面试笔记/录音转写/口述关键点，要求生成评价
- 用户提到：面试评价、初面评价、面试评估、interview evaluation、写个评价
- 用户要求对比候选人（需结合已有评价文件）

## 输入要求

Agent 需要从用户获取以下信息（缺失时主动询问）：

| 信息 | 必须 | 说明 |
|------|:----:|------|
| 面试记录/笔记 | ✅ | 文字转写、笔记文件、或口述要点 |
| 候选人姓名 | ✅ | |
| 目标岗位与级别 | ✅ | 如"系统策划 L3""PM" |
| 面试时长 | 建议 | 帮助判断信息密度 |
| 面试轮次 | 建议 | 初试/复试/终面 |
| 面试官 | 建议 | |
| 面试清单 | 建议 | 如果有对应的面试清单，评价时逐条对照更准确 |

## 执行步骤

### 1. 加载参考标准

按优先级查找：

1. **对应的面试清单**：如果该候选人已有面试清单（`*-面试清单.md` 或 `*-interview-checklist.md`），读取其评分维度和标准
2. **岗位能力标准**：参考 `interview-checklist` SKILL 中的「各岗位核心能力标准」
3. **reference/ 目录**：本目录下 `reference/` 中的标尺或评分标准文件

### 2. 分析面试记录

从记录中提取：

- 每个能力维度的**具体表现**（原文引用或要点摘要）
- **亮点时刻**：候选人展现出超预期能力的关键段落
- **风险信号**：回答中暴露的短板、矛盾、回避
- **关键证据**：可用于支撑结论的具体事实

### 3. 生成评价报告

按下方模板结构输出。

---

## 评价报告模板

### 一、候选人概况

```markdown
| 项目 | 信息 |
|------|------|
| 学历 | |
| 经验 | X 年；核心角色为 ... |
| 核心经历 | 公司A（项目，时段）→ 公司B → ... |
| 当前状态 | |
| 期望薪资 | |
```

### 二、初面评分

按岗位核心能力维度逐项打分：

```markdown
| 维度 | 对应主线 | 分数（1-5） | 简评 |
|------|----------|:-----------:|------|
| 维度1 | 第X主线 | X | 2-3句话概括表现 |
| ... | | | |

**综合：XX/YY**
```

**评分标准**：

| 分数 | 含义 |
|:----:|------|
| 5 | 显著超出岗位要求，有可迁移的方法论或体系 |
| 4 | 达到岗位要求，有清晰的实践证据 |
| 3 | 基本达标，但深度或广度不足，需进一步验证 |
| 2 | 低于岗位要求，有明显短板 |
| 1 | 严重不足或完全无相关经验 |

### 三、面试中的亮点

挑出 2-4 个最突出的正面信号，每个包含：

- **标题**：一句话概括
- **具体表现**：面试中的原文或行为描述
- **对标意义**：这个亮点对岗位匹配意味着什么

### 四、风险点

```markdown
| 风险 | 级别 | 初面判断 |
|------|:----:|----------|
| 风险描述 | 🔴高 / ⚠️中 / 低 | 面试中的具体表现和判断依据 |
```

风险级别说明：
- 🔴 **高**：可能导致不录用的结构性问题
- ⚠️ **中**：需要二面验证或入职后重点关注
- **低**：记录但不影响决策

### 五、面试主线逐条复盘

按面试清单中的主线（或能力维度），逐条写：

```markdown
### 第X线：主线名称

**面试表现**：
- 要点 1（含原文引用或行为描述）
- 要点 2
- ...

**判断**：一句话结论性评价
```

### 六、标杆对照（可选）

如果有同岗位的其他候选人评价，可做横向对比：

```markdown
| 维度 | 候选人A | 候选人B | 本候选人 |
|------|---------|---------|----------|
| 维度1 | | | |
| ... | | | |
| **独有优势** | | | |
```

### 七、综合判断与建议

```markdown
### 结论：录用 / 备选 / 不录用

（1-2 段文字概述核心判断理由）

### 建议录用方向（如为"备选"）

| 方案 | 岗位 | 理由 | 风险 |
|------|------|------|------|
| 方案A（推荐）| | | |
| 方案B | | | |

### 如果推进
- 二面重点考察：...
- 试用期作业建议：...
- 薪资参考：...
```

### 八、关键证据索引

```markdown
| 证据 | 面试原文位置 | 支撑判断 |
|------|-------------|----------|
| "原文引用或要点" | 时间戳/段落位置 | 对应哪个维度的判断 |
```

如果面试记录有时间戳，优先标注时间戳；如果是文本笔记，标注段落位置。

## 评价原则

### 证据优先

- 所有判断必须有面试中的具体行为或发言支撑
- 不做性格推测、不做能力臆想
- 候选人"没说"不等于"不会"，标注为"未验证"而非"不具备"

### 区分层次

面试评价需区分候选人的**能力层次**：

| 层次 | 信号 |
|------|------|
| **执行者** | "接到需求做事"，目标来源于上级，方案参考现有 |
| **独立贡献者** | 能定义问题、拆解方案、闭环交付，有自主判断 |
| **方法输出者** | 能从经验中抽象方法论，建立可复用的机制/框架 |
| **方向定义者** | 能定义团队方向、建立评判标准、影响组织决策 |

### 公平性

- 对同一岗位的不同候选人使用一致的评分维度和标准
- 明确区分"岗位不匹配"和"能力不足"
- 即使结论为"不录用"，也要写明客观优点（供其他团队参考）

### 结论三档

| 结论 | 含义 | 后续动作 |
|------|------|----------|
| **录用** | 能力匹配、风险可控 | 推进 offer 流程 |
| **备选** | 有亮点但存在结构性风险 | 二面验证 / 调整岗位定位 |
| **不录用** | 核心能力不达标或风险过高 | 写明原因，归档 |

## 输出约定

- 文件命名：`{候选人姓名}-初面评价.md` 或 `{候选人姓名}-面试评价.md`
- 存放位置（MyAgents 内）：与面试清单同目录，`面试/interviews/{候选人目录}/`
- 报告末尾附生成元信息（会话代号、标尺人物、面试转写来源）
- 评价完成后，更新 `面试/已面试索引.md`（如该文件存在）

## reference/ 目录说明

如果你在独立环境中使用本 SKILL，可在本目录下创建 `reference/` 子目录，放入：

```
reference/
├── 评分标准_{岗位}.md     # 自定义的评分标准（可选）
├── 标杆候选人_{姓名}.md   # 已有的标杆评价，用于横向对比
└── rubric_*.json          # 岗位标尺（可选）
```

## 禁止

- **不得编造**：面试记录中没有的内容不得出现在评价中
- **不得模糊判断**：每个维度必须给出明确分数和依据，不能只写"还行"
- **不得遗漏风险**：识别到的风险必须写入，不因"总体不错"而省略
- **不得泄露**：评价中包含薪资、内部对标等敏感信息，不得发送到非授权渠道
